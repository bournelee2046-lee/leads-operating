# 线索运营监控系统 - 中间层数据架构

## 概述

本文档描述线索运营监控系统的中间层数据架构设计，采用**混合型架构**，结合预计算和灵活查询的优势。

## 环境约束

| 项目 | 配置 |
|------|------|
| 硬件 | Mac mini M4 |
| 存储空间 | 256G (剩余130G) |
| 数据库大小 | 预计20-30G |
| 用户规模 | 10人以内 |
| 数据更新频率 | 日更或批量更新 |
| 部署方式 | 全本地 |

## 架构决策

### 核心技术栈

- **原始数据存储：** SQLite (现有 leads.db)
- **分析层存储：** DuckDB (高性能列存储)
- **查询服务：** Flask
- **缓存策略：** 内存缓存 (可选Redis)
- **前端：** React + TypeScript

### 架构分层图

```
┌─────────────────────────────────────────────────────┐
│              应用层 (Application Layer)              │
│  ┌──────────────┐  ┌──────────────┐  ┌───────────┐ │
│  │  仪表盘    │  │  数据探索   │  │  分析工具 │ │
│  └──────────────┘  └──────────────┘  └───────────┘ │
└─────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────┐
│          查询服务层 (Query Service Layer)            │
│         统一 API、路由、缓存、权限控制               │
└─────────────────────────────────────────────────────┘
                            ↓
        ┌───────────────────────┴───────────────────────┐
        ↓                                               ↓
┌──────────────────────────┐            ┌──────────────────────────┐
│   预计算层 (Precompute)  │            │   灵活查询层 (Flexible)  │
│      (DuckDB)           │            │      (SQLite)           │
│  - KPI指标             │            │  - 临时查询             │
│  - 日周月统计           │            │  - 复杂筛选             │
│  - 经销商汇总          │            │  - 自定义分组            │
│  - 渠道分析            │            │                        │
└──────────────────────────┘            └──────────────────────────┘
        └───────────────────────┬───────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────┐
│         原始数据层 (Raw Data Layer)                  │
│                leads.db (SQLite)                   │
└─────────────────────────────────────────────────────┘
```

## 核心设计原则

1. **性能优先** - 常用查询预计算，复杂查询优化
2. **存储可控** - 只存储必要的预计算结果
3. **易于扩展** - 插件化指标定义，灵活的数据模型
4. **低运维** - 简单的本地部署，最小化依赖
5. **数据一致性** - 明确的数据刷新机制

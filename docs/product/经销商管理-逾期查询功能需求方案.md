# 经销商管理「逾期查询」功能需求方案

> 编写日期：2026-05-18  
> 适用模块：经销商管理  
> 需求目标：在经销商管理中新增「逾期查询」入口，用于查询和导出首跟逾期线索明细，支撑大区、战区和门店维度的逾期跟进追踪。

---

## 一、需求背景

当前业务需要快速定位「首跟逾期」线索，即线索下发后未在规定时限内完成首次跟进的记录。现有经销商管理中已有「运营日报」入口，但缺少可直接按组织和门店筛选的逾期明细查询能力。

本需求在【经销商管理】新增【逾期查询】卡片，进入后可按大区、战区、店编号、店简称和日期范围查询首跟逾期线索。首跟逾期定义为：`一级渠道 = 线上`、首跟截止时间不为空、`是否及时跟进 = 否`。页面展示线索下发、首跟截止、首跟、二跟、三跟、渠道、状态和跟进人等关键字段。

---

## 二、功能范围

### 2.1 新增入口

在【经销商管理】页面中，将现有「预留卡片二」改造为逾期查询入口：

| 项目 | 内容 |
|:---|:---|
| 卡片名称 | 逾期查询 |
| 卡片说明 | 查询首跟逾期线索明细 |
| 入口路径 | `/dealer-management/overdue-query` |
| 建议图标 | `ClockAlert` 或 `AlertTriangle` |
| 默认权限 | 有「逾期查询入口」权限的账号可见 |

### 2.2 查询页面

点击【逾期查询】进入明细查询页面，页面包含：

1. 顶部返回按钮和页面标题「逾期查询」。
2. 查询筛选区。
3. 结果统计区。
4. 明细表格区。
5. 导出按钮。

## 三、查询条件

| 条件 | 类型 | 是否必填 | 说明 |
|:---|:---|:---:|:---|
| 大区 | 下拉多选 | 否 | 来源于门店/线索组织字段；未选择表示全部大区 |
| 战区 | 下拉多选 | 否 | 与大区联动；未选择表示全部战区 |
| 店编号 | 输入框 | 否 | 支持精确匹配；建议去除前后空格 |
| 店简称 | 输入框 | 否 | 支持模糊匹配 |
| 日期范围 | 日期区间 | 是 | 默认按「线索最终下发时间」筛选，建议默认最近 7 天 |

日期范围口径建议：

- 主口径：`线索表.最终下发时间` 落在所选日期范围内。
- 原因：业务关注线索下发后的首跟是否逾期，用最终下发时间做筛选更贴近线索产生和分配周期。
- 待确认项：如业务希望按首跟截止时间统计，可在筛选区增加「日期口径」下拉，支持「最终下发时间 / 首跟截止时间」切换；首跟截止时间对应当前字段 `跟进截止时间`。

## 四、数据口径

### 4.1 首跟逾期定义

首跟逾期线索需同时满足以下条件：

```text
线索表.一级渠道 = '线上'
AND 线索表.跟进截止时间 IS NOT NULL
AND TRIM(线索表.跟进截止时间) != ''
AND 线索表.是否及时跟进 = '否'
```

说明：

- 业务口径中的「首跟截止时间」对应当前线索表字段 `跟进截止时间`。
- 只有线上渠道且存在首跟截止时间的线索才进入逾期查询范围。

兼容处理：

- 空值、`NULL` 不默认视为逾期，避免误伤无法判断的数据。
- `一级渠道` 为空、非「线上」或 `跟进截止时间` 为空的线索不进入首跟逾期范围。
- 如后续业务确认 `是否及时跟进` 空值也需要纳入逾期，可扩展为 `是否及时跟进 != '是'`。

### 4.2 日期过滤

默认使用：

```text
DATE(线索表.最终下发时间) >= 开始日期
AND DATE(线索表.最终下发时间) <= 结束日期
```

如 `最终下发时间` 为空，则该记录不进入默认日期范围查询结果。

### 4.3 跟进人关联

跟进人需要关联跟进明细表，推荐关联规则：

```text
线索表.id = 跟进表.门店线索id
```

跟进人取值规则：

1. 优先取该线索最早一条跟进明细的 `跟进人`。
2. 如可通过跟进时间匹配到 `首跟时间` 对应记录，则优先取首跟记录的 `跟进人`。
3. 如存在人员表，可展示人员姓名；否则展示跟进表中的跟进人编号/原值。
4. 同一线索存在多条跟进明细时，列表只展示一个跟进人，导出可按相同规则输出。

实现注意：

- 现有 `mart_customer_visit` 只装载有进店时间的跟进记录，不能代表完整跟进明细。
- 本需求应新增完整跟进明细集市表，或在接口查询时直接关联原始 `跟进表`。

## 六、页面交互

### 6.1 初始状态

- 页面默认展示最近 7 天首跟逾期数据。
- 日期范围必填，未选择时不允许查询。
- 默认按 `线索最终下发时间` 倒序排列。

### 6.2 查询

点击【查询】后：

1. 校验日期范围。
2. 调用逾期查询接口。
3. 刷新统计卡和明细表。

筛选条件为空时表示不限制该维度。

### 6.3 重置

点击【重置】后：

- 清空大区、战区、店编号、店简称。
- 日期恢复为最近 7 天。
- 重新查询默认结果。

### 6.4 表格能力

表格需支持：

- 分页。
- 加载中状态。
- 空数据提示。
- 按线索最终下发时间、首跟截止时间排序。
- 长文本省略并支持悬浮查看完整内容。

### 6.5 导出

点击【导出】后，按当前筛选条件导出 Excel。

导出字段与页面展示字段保持一致，文件名建议：

```text
逾期查询_YYYYMMDD-YYYYMMDD.xlsx
```

## 八、接口建议

### 8.1 查询接口

```text
GET /api/dealer-management/overdue-query
```

请求参数：

| 参数 | 类型 | 必填 | 说明 |
|:---|:---|:---:|:---|
| start_date | string | 是 | 开始日期，格式 `YYYY-MM-DD` |
| end_date | string | 是 | 结束日期，格式 `YYYY-MM-DD` |
| regions | string | 否 | 多个大区用英文逗号分隔 |
| zones | string | 否 | 多个战区用英文逗号分隔 |
| dealer_id | string | 否 | 店编号 |
| dealer_name | string | 否 | 店简称 |
| page | number | 否 | 默认 1 |
| page_size | number | 否 | 默认 20 |
| sort_by | string | 否 | 默认 `assign_time` |
| sort_order | string | 否 | `desc` / `asc` |

响应结构：

```json
{
  "success": true,
  "data": {
    "summary": {
      "overdue_count": 128,
      "dealer_count": 36,
      "first_followed_count": 91,
      "not_first_followed_count": 37
    },
    "items": [],
    "pagination": {
      "page": 1,
      "page_size": 20,
      "total": 128
    }
  }
}
```

### 8.2 导出接口

```text
GET /api/dealer-management/overdue-query/export
```

请求参数与查询接口一致，不需要分页参数。

## 九、数据实现建议

### 9.1 推荐集市表调整

当前 `mart_leads` 已包含：

- `lead_id`
- `dealer_id`
- `dealer_name`
- `region`
- `channel_1`
- `channel_2`
- `channel_3`
- `assign_time`
- `first_follow_time`
- `is_followed_in_30min`
- `follow2_time`
- `follow_cutoff_time`
- `lead_status`

本需求建议补充：

| 表 | 字段 | 原始来源 | 说明 |
|:---|:---|:---|:---|
| mart_leads | follow3_time | 线索表.三跟时间 | 当前页面必展字段 |
| mart_leads | timely_follow_text | 线索表.是否及时跟进 | 保留原始「是/否」展示值 |

同时新增完整跟进明细表：

```text
mart_follow_detail
```

建议字段：

| 字段 | 来源 |
|:---|:---|
| lead_id | 跟进表.门店线索id |
| dealer_id | 跟进表.门店编码 |
| follower_id | 跟进表.跟进人 |
| follower_name | 人员表.姓名 |
| follower_role | 跟进表.跟进人角色 |
| followup_created_time | 跟进表.创建时间 |
| created_at | 系统时间 |
| updated_at | 系统时间 |

### 9.2 查询逻辑示例

```sql
WITH first_follow_user AS (
  SELECT
    fd.lead_id,
    COALESCE(NULLIF(fd.follower_name, ''), fd.follower_id) AS follower,
    ROW_NUMBER() OVER (
      PARTITION BY fd.lead_id
      ORDER BY fd.followup_created_time ASC NULLS LAST
    ) AS rn
  FROM mart_follow_detail fd
)
SELECT
  l.region,
  d.zone,
  l.dealer_id,
  l.dealer_name,
  l.assign_time,
  l.follow_cutoff_time,
  '否' AS timely_follow_text,
  l.first_follow_time,
  l.follow2_time,
  l.follow3_time,
  l.lead_status,
  l.channel_1,
  l.channel_2,
  l.channel_3,
  ffu.follower
FROM mart_leads l
LEFT JOIN mart_dealers d
  ON l.dealer_id = d.dealer_id
LEFT JOIN first_follow_user ffu
  ON l.lead_id = ffu.lead_id AND ffu.rn = 1
WHERE l.timely_follow_text = '否'
  AND l.channel_1 = '线上'
  AND l.follow_cutoff_time IS NOT NULL
  AND DATE(l.assign_time) BETWEEN :start_date AND :end_date
```

如本期不新增 `timely_follow_text`，可临时使用：

```sql
l.is_followed_in_30min = false
```

但仍必须叠加：

```sql
l.channel_1 = '线上'
AND l.follow_cutoff_time IS NOT NULL
```

页面展示仍建议返回「否」，避免用户看到布尔值。

## 十一、验收标准

1. 经销商管理页可看到【逾期查询】卡片，点击后进入逾期查询页面。
2. 无入口权限的账号不显示【逾期查询】卡片。
3. 支持按大区、战区、店编号、店简称、日期范围组合查询。
4. 查询结果仅包含同时满足 `一级渠道 = 线上`、首跟截止时间不为空、`是否及时跟进 = 否` 的线索。
5. 日期范围默认按 `线索最终下发时间` 过滤。
6. 明细表展示以下字段：线索最终下发时间、首跟截止时间、是否及时跟进、首跟时间、二跟时间、三跟时间、线索状态、一级渠道、二级渠道、三级渠道、跟进人。
7. 跟进人通过跟进明细表关联获取，同一线索多条跟进明细时按规则取首条。
8. 支持分页、排序、空数据、加载中和错误提示。
9. 支持按当前筛选条件导出 Excel，导出字段与页面一致。
10. 输入某一门店的店编号，并将开始日期和结束日期选择为同一天时，系统应返回该门店该日期下所有首跟逾期线索明细；点击导出后，Excel 应包含与当前筛选结果一致的全部明细数据，不受页面分页影响。
11. 查询和导出接口均受权限控制。

## 十二、待确认问题

1. 日期范围最终以 `线索最终下发时间` 为准，还是需要支持切换为首跟截止时间。
2. `是否及时跟进` 空值是否要计入逾期；当前 PRD 按不计入处理。
3. 跟进人展示员工姓名、员工编号，还是姓名和编号同时展示。
4. 是否需要展示线索 ID、手机号脱敏、逾期时长等辅助排查字段。
5. 导出是否需要限制最大条数，避免一次导出过大影响服务稳定性。

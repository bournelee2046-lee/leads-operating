# 导出Excel弹窗功能 — 产品文档（V2.1）

## 一、这个功能是做什么的

在【运营日报】页面点击【导出Excel】后，会弹出一个窗口。窗口顶部有两个 Tab 标签页，分别对应两种导出场景：

| Tab | 名字 | 适用场景 | 输出格式 |
|:---|:---|:---|:---|
| 第一个 | **导出日报** | "把截至今天的数据，填进标准日报模板" | 按 `线索运营日报模板.xlsx` 填写，保留模板样式 |
| 第二个 | **自定义导出** | "我想看某段时间的数据，自己留着分析" | 从零生成新的 Excel，表头写明所选时间范围 |

两个 Tab 独立运作，各自的日期选择和导出逻辑互不影响。

### 导出的 Excel 文件结构（Tab 一：导出日报）

导出日报生成的 Excel 包含 **两个 Sheet**：

| Sheet | 名称 | 内容 |
|:---|:---|:---|
| Sheet 1 | 店端日报 | 每个门店一行，按模板格式填入门店级数据 |
| Sheet 2 | 大区日报 | 按大区汇总店端数据，末尾含合计行 |

> **Tab 二（自定义导出）**：V2.1 仅输出一个 Sheet（门店明细），大区汇总为后续版本扩展。

---

## 二、怎么操作（用户视角）

### 入口

运营日报页面顶部，找到 **【导出Excel】** 按钮，点击即可。

### Tab一：导出日报

1. 弹窗默认打开"导出日报"标签页
2. 选择一个坐标日期（如 5月13日）
3. 点击【筛选】→ 系统校验日期是否已选
4. 等待 3 秒倒计时（按钮上会显示"导出(3s)" → "导出(2s)" → "导出(1s)" → "导出"）
5. 倒计时结束后，点击【导出】→ 浏览器自动下载 Excel 文件

下载的 Excel 里：

**Sheet 1「店端日报」：**
- 表头、样式、合并单元格跟模板一模一样
- E-P 列填的是"这个月1号到选定日期"的累计值
- Q-Y 列填的是"选定日期当天"的值

**Sheet 2「大区日报」：**
- 表头、样式、合并单元格跟模板一模一样
- 每一行 = 一个大区 = 该大区下所有门店的合计值
- 比率类指标（如 30分钟跟进率）采用"先合计分子分母，再除"的方式计算（详见 3.4）
- 最后一行是「合计」行：A、B 列合并为一格显示"合计"，其值 = 所有大区的总计

### Tab二：自定义导出

1. 切换到"自定义导出"标签页
2. 选择起始日期和结束日期（如 5月1日 至 5月10日）
3. 点击【筛选】→ 系统校验日期是否合法
4. 等待 3 秒倒计时
5. 点击【导出】→ 下载 Excel 文件

下载的 Excel 里：
- 表头从零生成，每列的标题会带上日期范围（如 `2026-05-01至2026-05-10_线索量`）
- 所有指标都按选定的时间段累计计算
- 一列一个指标，没有"本月/本日"的拆分

### 通用操作规则

- 日期没选或选错了，系统会提示
- 倒计时期间改日期或切 Tab，倒计时会中断，需重新点【筛选】
- 导出后弹窗不关闭，方便再导一次
- 点右上角 ✕ 或点击遮罩区可关闭弹窗

## 三、核心逻辑

### 3.1 Tab一"导出日报"的数据计算 — 店端日报

**用户只选一个坐标日期。** 比如选 2026-05-13：

| 区域 | 计算方式 | 本例实际取值 |
|:---|:---|:---|
| E-P 列（本月） | 所选日期所在月的1号 → 所选日期 | 2026-05-01 → 2026-05-13 |
| Q-Y 列（本日） | 所选日期当天 | 2026-05-13 |

#### 为什么是单一坐标日期而不是日期范围

| 对比维度 | 双日期（旧设计） | 单日期（新设计） |
|:---|:---|:---|
| 用户操作 | 选起始日期 + 结束日期 | 只选一个日期 |
| "本月"语义 | 起始日期所在月（起始日期的天被丢弃，无意义） | 所选日期所在月（天然正确） |
| "本日"语义 | 结束日期当天 | 所选日期当天 |
| 跨月场景 | 会产生"本月跨两个月"的语义矛盾 | 不存在这个问题 |

日报模板本身的表头是"本月/本日"，天然是一个"截止某日"的快照概念，和单一坐标日期完全匹配。日期范围是另一个独立需求，通过 Tab 二来满足。

#### 模板填写方式

系统会加载 `线索运营日报模板.xlsx`，先填充"店端日报"工作表，再填充"大区日报"工作表，保留所有原有样式。

### 3.2 Tab一"导出日报"的数据计算 — 大区日报

大区日报的数据完全由店端日报的数据派生而来，**不重新查询数据库**。计算步骤：

1. 拿到店端日报各门店的月度数据和日度数据（同 3.1 的查询结果）
2. 按 `大区`（region）分组
3. 对每个大区，根据列的类型执行不同汇总逻辑（详见 3.4）
4. 按 M 行大区数据 + 1 行合计的方式写入模板

#### 大区日报的模板结构

| 行号 | 内容 |
|:---|:---|
| 第 1 行 | 标题：`线索运营日报-大区（截止时间{日期}）` |
| 第 2-4 行 | 表头（三层合并单元格，系统不修改） |
| 第 5 行起 | 大区数据（每个大区一行） |
| 末尾行 | 合计行 |

#### 门店总数列（B 列）的说明

B 列显示该大区下有多少家门店参与了统计，即 `COUNT(DISTINCT dealer_id)`。

### 3.3 合计行规范

合计行位于所有大区数据行之后，具体规则：

**单元格合并：**
- A 列和 B 列合并为一个单元格，显示文字「合计」

**数值计算：**
- 绝对值列：所有大区该列的 SUM（等价于全量门店的 SUM）
- 比率列：先对所有大区分别 SUM 分子和分母，再用 `分子合计 / 分母合计` 计算

**样式：**
- 合并单元格水平居中、垂直居中
- 推荐加粗，与数据行区分

**合计行格式示例：**

```
 ┌──────┬──────┬────────┬──────┬───────────────┬───┐
 │ 合计 │      │ 12345  │ 8900 │     72.11%    │...│
 │  (A+B 合并)  │(C列)  │(D列) │   (G列比率)   │   │
 └──────┴──────┴────────┴──────┴───────────────┴───┘
```

### 3.4 大区日报各列的汇总方式

这是最核心的部分。大区日报的列分为两类：**绝对值列**和**比率列**。

#### 绝对值列（直接 SUM 大区内所有门店的值）

| 列号 | 时间维度 | 指标名 | 汇总方式 |
|:---|:---|:---|:---|
| C | 本月 | N60线索数 | SUM(n60_lead_count) |
| D | 本月 | N60及时跟进数 | SUM(n60_follow_30min_count) |
| E | 本月 | 30分钟跟进任务数(首触) | SUM(follow_30min_task_count) |
| F | 本月 | 30分钟及时跟进数(首触) | SUM(follow_30min_count) |
| H | 本月 | 三天三次跟进任务数 | SUM(day3_3follow_task_count) |
| I | 本月 | 三天三次跟进数 | SUM(day3_3follow_count) |
| K | 本月 | 新媒体自店有效线索量 | 暂无数据源，留空 |
| L | 本月 | 线索量（本地） | SUM(local_lead_count) |
| M | 本月 | 到店数 | SUM(to_shop_count) |
| O | 本日 | N60线索数 | SUM(n60_lead_count) |
| P | 本日 | N60及时跟进数 | SUM(n60_follow_30min_count) |
| Q | 本日 | 30分钟跟进任务数(首触) | SUM(follow_30min_task_count) |
| R | 本日 | 30分钟及时跟进数(首触) | SUM(follow_30min_count) |
| T | 本日 | 新媒体自店有效线索量 | 暂无数据源，留空 |
| U | 本日 | 线索量（本地） | SUM(local_lead_count) |
| V | 本日 | 到店数 | SUM(to_shop_count) |

#### 比率列（先合计分子分母，再计算比率）

**重要：** 不能对门店的比率取平均。必须先把大区内所有门店的分子、分母分别 SUM，再用 `SUM(分子) / SUM(分母)` 计算。

| 列号 | 时间维度 | 比率名 | 分子 | 分母 | 公式 |
|:---|:---|:---|:---|:---|:---|
| G | 本月 | 30分钟跟进率（首触） | F列(及时跟进) | E列(任务数) | `SUM(F) / SUM(E)` |
| J | 本月 | 三天三次跟进率 | I列(跟进数) | H列(任务数) | `SUM(I) / SUM(H)` |
| N | 本月 | 线索到店率（本地） | M列(到店数) | L列(线索量本地) | `SUM(M) / SUM(L)` |
| S | 本日 | 30分钟跟进率（首触） | R列(及时跟进) | Q列(任务数) | `SUM(R) / SUM(Q)` |
| W | 本日 | 线索到店率（本地） | V列(到店数) | U列(线索量本地) | `SUM(V) / SUM(U)` |

**示例：** 华南大区有 3 家门店：

| 门店 | 及时跟进(F) | 任务数(E) | 直接算比率 | 正确做法 |
|:---|:---|:---|:---|:---|
| 门店1 | 50 | 100 | 50% | |
| 门店2 | 30 | 40 | 75% | |
| 门店3 | 0 | 0 | - | |
| **华南大区** | **80** | **140** | ❌ AVG(50%,75%) = 62.5% | ✅ 80/140 = 57.1% |

> 门店1 任务多但跟进率低，门店2 任务少但跟进率高。如果简单取平均（62.5%），就忽略了任务量的权重差异。正确的做法是分子分母分别合计后再除（80/140=57.1%），这与业务直觉一致。

### 3.5 Tab二"自定义导出"的数据计算

**用户选起始日期和结束日期。** 比如选 2026-05-01 至 2026-05-10：

- 所有指标都按 2026-05-01 → 2026-05-10 这个时间段累计计算
- 表头动态生成，每列标题带日期范围后缀
- 从零生成新 Excel（不依赖日报模板）
- V2.1 仅输出一个 Sheet（门店明细），大区汇总为后续版本

#### 为什么自定义导出不依赖日报模板

自定义导出和日报导出是两个独立场景：

| | 导出日报 | 自定义导出 |
|:---|:---|:---|
| 数据需求 | 按固定模板格式填数据 | 按时间范围灵活查数据 |
| 表结构 | 模板说了算 | 按需要生成 |
| 输出格式 | 标准日报格式（有合并单元格、样式） | 简洁数据表格 |
| 换模板影响 | 需要更新映射配置 | 不受影响 |

### 3.6 字段映射配置（Tab一的核心）

#### 设计原则

日报模板里的列 → 系统字段的对应关系，不再硬编码在代码里，而是抽到一个独立的 **CSV 配置文件** 中。好处是：

- 模板调整列顺序 → 改 CSV 一行即可，不用改代码
- 模板新增/删除字段 → 改 CSV 即可
- 配完一目了然，不需要翻代码就能确认"哪个数据去了哪一列"

#### CSV 配置文件格式

文件名：`templates/线索运营日报模板-字段映射.csv`，和模板文件放在 `templates/` 目录下。

#### CSV 规则说明

1. `Sheet`：目标工作表名，`店端日报` 或 `大区日报`
2. `列号`：Excel 列字母
3. `时间维度`：`本月` = 用月维度数据填充，`本日` = 用日维度数据填充，`通用` = 门店基础信息
4. `计算类型`（大区日报专属）：`绝对值` → 直接 SUM，`比率` → 分子分母分别 SUM 再除
5. `系统字段名/公式`：
   - 店端日报/大区日报绝对值：数据库查询结果中对应的字段名
   - 大区日报比率：`分子字段/分母字段` 格式
6. `Excel表头名`：仅供参考；系统实际识别以列号和计算类型为准

#### M 列和 V 列、K 列和 T 列的说明

M 列（店端·新媒体自店有效线索量）、V 列（店端·本日新媒体自店有效线索量）、K 列（大区·新媒体自店有效线索量）、T 列（大区·本日新媒体自店有效线索量）当前系统暂无数据源，CSV 中不配置，导出的 Excel 中这些列保持为空。

```
│                                                      │
└──────────────────────────────────────────────────────┘

当选中【自定义导出】时，日期区域变为：

│  日期范围                                            │
│  ┌──────────────┐      ┌──────────────┐              │
│  │ 起始日期      │  至  │ 结束日期      │              │
│  └──────────────┘      └──────────────┘              │
│                                                      │
│  说明：所有指标按选定日期范围累计计算                   │
```

### Tab 切换行为

- 默认选中"导出日报"
- 切换 Tab 时，之前 Tab 的日期选择保留（切回来还在）
- 切换 Tab 时，倒计时中断，导出按钮恢复禁用状态
- 两个 Tab 拥有各自独立的【筛选】/【清空】/【导出】按钮

---

## 五、按钮怎么工作的

| 按钮 | 什么时候可用 | 作用 |
|:---|:---|:---|
| 【筛选】 | 任何时候（但日期不合法会提示） | 校验日期 → 启动3秒倒计时 |
| 【清空】 | 任何时候 | 清空当前 Tab 的日期 → 中断倒计时 → 导出按钮变灰 |
| 【导出】 | 倒计时结束后才可点击 | 调用后台生成 Excel → 浏览器下载 |
| 【✕】 | 任何时候 | 关闭弹窗（两个 Tab 的日期状态保留，下次打开还在） |
| 切换 Tab | 任何时候 | 保留原 Tab 状态，展示新 Tab 内容 |

### 两个 Tab 的按钮状态

| | 导出日报 | 自定义导出 |
|:---|:---|:---|
| 各自的日期变量 | `selectedDate` | `startDate` + `endDate` |
| 各自的倒计时 | `countdown1` | `countdown2` |
| 各自的导出状态 | `exporting1` | `exporting2` |
| 切换时 | 保留状态不动 | 保留状态不动 |

## 六、导出失败怎么办

| 情况 | 提示内容 |
|:---|:---|
| 日期没选（导出日报） | "请选择日期" |
| 日期没选全（自定义导出） | "请选择起始日期和结束日期" |
| 起始日期晚于结束日期 | "起始日期不能晚于结束日期" |
| 日期范围内没有数据 | "该日期范围暂无数据，请调整筛选条件" |
| 网络有问题 | "导出失败，请检查网络后重试" |
| 后台报错了 | "导出失败，请联系管理员" |

# 线上线索漏斗目标达成分析 — 生产加固优化 PRD

> 版本：基于一期（5月17日）的5项生产加固  
> 编写日期：2026-05-18  
> 状态：已上线验证

---

## 一、背景

线上线索漏斗目标达成分析功能于 2026-05-17 首次部署到生产环境。运行后发现以下问题影响正常使用：

1. 首页「同步新数据」按钮无法使用，提示"无法连接到后端服务"
2. 全量刷新后，已配置的成交目标、转化率、车型映射等配置数据丢失
3. 提交成交目标 Excel 时报错"Object of type datetime is not JSON serializable"
4. 上传本地最新 `leads.db` 后，配置数据随 DuckDB 重置而清空

本次优化目标：解决上述问题，确保配置数据在任何情况下不丢失，确保同步按钮正常工作。

---

## 二、功能需求

### 2.1 配置数据持久化

**现状**：用户手动配置的成交目标（Excel 导入）、转化率、车型映射、全国到店目标仅保存在 DuckDB 分析数据库中。全量刷新或 DuckDB 文件损坏时，配置数据丢失。

**需求**：系统需保证配置数据在以下场景下不丢失：
- 用户点击全量刷新
- 服务器重启且 DuckDB 文件损坏
- 运维更新 `leads.db` 后重建 DuckDB

**实现**：
- 全量刷新前自动备份 4 张配置表到内存 + JSON 文件
- 全量刷新后自动恢复配置
- DuckDB 被删除时从 JSON 文件恢复

### 2.2 同步新数据功能修复

**现状**：首页「同步新数据」按钮调用后端时因 nginx 超时和 DuckDB 锁冲突导致失败。

**需求**：点击「同步新数据」后，系统应完成增量数据同步并自动刷新仪表盘。

**实现**：
- Nginx 代理超时从 60s 提升至 300s
- 后端同步前释放 DuckDB 连接避免锁冲突
- 前端请求带上 session cookie 完成认证

### 2.3 成交目标提交修复

**现状**：上传成交目标 Excel 后报错，无法完成提交。

**需求**：上传成交目标 Excel 后正常入库并显示提交结果。

**实现**：修复返回数据中 datetime 对象序列化问题。

## 三、影响范围

### 3.1 涉及的配置表（受持久化保护）

| 配置表 | 来源 | 保护方式 |
|--------|------|---------|
| `funnel_sales_targets`（成交目标） | Excel 导入 | 内存 + JSON 备份恢复 |
| `funnel_conversion_rates`（转化率） | Web 配置面板 | 内存 + JSON 备份恢复 |
| `funnel_model_mapping`（车型映射） | Web 配置面板 | 内存 + JSON 备份恢复 |
| `funnel_national_visit_targets`（到店目标） | Web 配置面板 | 内存 + JSON 备份恢复 |

### 3.2 不受影响的表

以下为系统自动计算生成，每次全量刷新后重新计算，不在持久化保护范围：

- `funnel_metric_daily`、`funnel_metric_monthly`、`funnel_metric_targets`
- `funnel_model_source_values`、`funnel_import_logs`

## 四、用户使用说明

### 4.1 同步新数据

1. 登录系统后，在首页右上角点击「同步新数据」
2. 按钮显示「同步中...」（约 1-2 分钟）
3. 完成后自动刷新仪表盘数据

### 4.2 上传成交目标

1. 进入漏斗目标分析配置页面
2. 上传成交目标 Excel 文件
3. 系统自动入库并显示汇总结果

### 4.3 运维更新数据

如需更新 `leads.db` 到服务器，按以下顺序操作：

1. 先在云服务器触发一次全量刷新（确保配置快照是最新的）
2. 停止服务
3. rsync 新 `leads.db` 到服务器
4. 删除 `leads_analytics.db`
5. 启动服务，系统自动恢复配置

---

## 五、技术约束

1. **全量刷新耗时约 2-3 分钟**，期间用户在首页等待。
2. **JSON 备份文件**路径：`data/funnel_config_backup.json`，约 700KB（含 2,300+ 行成交目标），请勿手动删除。
3. 增量同步（约 1.5 分钟）不触发备份恢复，不影响配置数据。
4. Gunicorn worker timeout 已提升至 360 秒（原 120 秒），避免全量刷新被 SIGKILL。

## 六、验收标准

| 功能 | 验收标准 |
|------|---------|
| 同步新数据 | 点击按钮后正常完成同步，仪表盘数据刷新 |
| 全量刷新 | 完成后 4 张配置表数据不丢失，`funnel_config_backup.json` 更新 |
| 配置提交 | 成交目标/转化率/车型映射/到店目标提交不报错 |
| DuckDB 重建 | 删除 `leads_analytics.db` 重启后，配置自动恢复 |
| 数据库同步 | rsync 新 `leads.db` 后配置从 JSON 文件恢复 |

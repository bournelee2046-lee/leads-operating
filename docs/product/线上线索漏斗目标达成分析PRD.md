# 线上线索漏斗目标达成分析 PRD

> **文档版本**：V1.2  
> **创建日期**：2026-05-17  
> **适用产品**：线索运营监控系统  
> **目标读者**：线索运营负责人、数据产品经理、数据分析师、研发人员

---

## 一、产品概述

### 1.1 需求背景

线索运营管理的核心目标，是管理全国门店从线上线索到进店、再到成交的完整转化过程。当前业务最关注的核心指标是**到店数及达成进度**，但单独观察到店数无法回答进度不足的原因：

- 是线上线索量不足？
- 是线索质量不足？
- 是门店邀约到店转化不足？
- 是某个车型拖累？
- 是某个渠道供给或质量问题？
- 当前到店是否足以支撑成交目标？

因此，需要建设一套独立的线上线索销售漏斗分析功能，以「线上线索量 -> 有效线索量 -> 到店数 -> 成交数」为主链路，结合全国到店目标和成交目标倒推，形成全国、大区、门店、车型、渠道多层级的目标达成监控能力。

### 1.2 产品定位

本功能定位为**线上线索漏斗目标达成分析工具**，用于日常监控当月线上线索到店目标和成交目标支撑情况。

它不是简单的数据明细查询页，而是一个面向管理动作的分析模块。第一入口应优先服务区域负责人日常管理场景：每天数据同步后，先快速看到所辖范围内不同进度状态的门店数量，再定位具体落后门店，最后按车型和渠道下钻原因。

1. 在首页快速判断全国当月到店进度是否健康。
2. 进入专题页后默认展示区域负责人驾驶舱，快速识别进度状态、问题大区、问题战区和问题门店。
3. 在驾驶舱内通过点击状态卡、大区、战区或诊断标签，同页联动下方「大区 x 门店」列表。
4. 锁定具体门店后，再进入门店 x 车型和门店 x 车型 x 渠道明细，判断问题来自线索量、线索质量、到店转化、车型结构还是渠道供给。
5. 支持月中调整目标和转化率后重新计算进度。

### 1.3 建设原则

- **独立口径**：本功能重新构建独立指标表，不直接复用现有 DuckDB 指标表，避免与运营日报等已有指标口径混用。
- **线上优先**：所有线索、目标分解、漏斗计算均只考虑线上线索，线下线索始终不参与。
- **目标双轨**：全国到店目标分解和成交目标倒推分别展示，不合并为唯一目标。
- **首页前置**：作为高优先级功能，首页直接展示全国当月核心进度。
- **驾驶舱优先**：专题页默认进入面向区域负责人的驾驶舱，而不是直接进入明细查询表。
- **同页联动**：核心状态卡、大区/战区汇总和诊断标签点击后，同页刷新门店列表，减少运营人员在页面之间跳转。
- **支持下钻**：围绕「门店 x 车型 x 渠道」逐层定位问题。
- **源值可见**：车型映射配置应直接呈现当前源数据中真实存在的车型值，而不是依赖外部手工提供的全量映射表。
- **未映射不丢失**：未完成车型映射的数据仍进入实际总量和明细分析，但不参与成交目标倒推。
- **数据进度驱动目标达成**：时间进度用于展示自然月进展；目标达成、应达到店和缺口按最新线上线索数据日期对应的数据进度计算。
- **可演进**：第一版支持手动配置转化率，后续补充历史趋势参考和自动计算能力。

## 二、用户与场景

### 2.1 目标用户

| 用户角色 | 核心诉求 |
| :--- | :--- |
| 全国线索运营负责人 | 关注全国到店进度、目标缺口、问题区域和问题门店 |
| 大区 / 战区管理人员 | 关注本区域门店进度和责任归属 |
| 线索运营区域负责人 | 关注所辖门店的到店达成、车型结构和渠道表现 |
| 线索运营-区域支持 | 辅助定位门店问题，跟踪改善动作 |

### 2.2 核心使用场景

1. 用户打开首页，查看当月全国到店目标是否按时间进度达成。
2. 区域负责人进入专题页驾驶舱，查看自己负责范围内各进度状态门店数量，以及各大区、战区的门店状态分布。
3. 区域负责人点击「严重落后」「轻度落后」或某个大区/战区卡片后，下方门店列表同页刷新为对应门店。
4. 区域负责人在门店列表中锁定落后门店，查看缺口、达成率、负责人、区域支持和初步诊断标签。
5. 若需要解释具体原因，再从门店列表进入门店 x 车型，进一步下钻门店 x 车型 x 渠道。
6. 月中调整全国到店目标或成交转化率后，重新查看达成情况。
7. 随着历史数据积累，使用历史趋势值辅助判断手动转化率是否合理。

### 2.3 驾驶舱核心用户旅程

第一版驾驶舱采用「先发现问题，再同页定位门店，再下钻解释原因」的使用路径。

```text
首页线上线索漏斗目标达成模块
  ↓
区域负责人驾驶舱
  ↓ 点击状态卡 / 大区卡 / 战区卡 / 诊断标签
同页联动大区 x 门店列表
  ↓ 点击门店的查看车型
门店 x 车型明细
  ↓ 点击渠道分析
门店 x 车型 x 渠道明细
```

交互原则：

- 驾驶舱不以复杂图表为主，优先使用状态卡、简洁条形分布、汇总列表和门店主表。
- 点击核心信息后不直接跳离驾驶舱，而是刷新同页下方门店列表。
- 只有当用户需要解释具体门店原因时，才进入明细分析。

## 三、核心业务口径

### 3.1 数据范围

本功能中所有线索类指标均仅统计线上线索。

```text
线索范围 = 一级渠道 = '线上'
```

说明：

- 一级渠道为空、线下或其他非线上线索不参与本功能的线索量、有效线索量、目标分解和转化率计算。
- 全国到店目标分解时，分母也只使用全国累计线上线索量。
- 线索必须归属于当前门店表中的有效门店；线索归属门店不在当前门店表内的记录，不进入本功能统计范围。
- 各层级口径需保证门店范围对等：全国、区域、门店的线索、到店、成交和目标分解，均基于同一套当前门店表门店集合计算。

### 3.1.1 门店范围对齐规则

由于线索表中的线索归属门店可能超过当前门店表中的门店范围，本功能需要先按当前门店表做门店范围过滤。

示例：

```text
本月线上线索总量 = 100,000
其中归属于当前门店表门店的线上线索 = 97,000
其中归属于非当前门店表门店的线上线索 = 3,000
```

则本功能中的全国线上线索量应取：

```text
全国线上线索量 = 97,000
```

剩余 3,000 条线索不参与：

- 全国线上线索量
- 门店线上线索占比
- 全国到店目标分解
- 线索有效率、到店率、成交率等转化指标
- 大区、战区、门店、车型、渠道分析

该规则的原则是：本功能所有指标均以当前门店表定义的门店集合为管理边界，避免线索分母包含无法归属到当前管理门店的记录。

### 3.2 指标定义

| 指标 | 口径 |
| :--- | :--- |
| 线上线索量 | 当月或筛选周期内，一级渠道 = '线上'，且归属门店存在于当前门店表中的线索数量 |
| 有效线索量 | 线上线索中，`线索状态 = 跟进中` 的线索数量 |
| 线索有效率 | 有效线索量 / 线上线索量 |
| 到店记录数 | 客流明细中的原始进店记录条数，仅作为辅助排查字段 |
| 到店数 | 等同当前客流统计中的「线上进店客流」；同一线索同一门店同一天多次到店只算 1，不跨日去重，不全局去重 |
| 成交数 | 线上实销表成交记录数，排除 `四级渠道 = APP订单-排产定` |
| 线索到店率 | 到店数 / 线上线索量 |
| 有效线索到店率 | 到店数 / 有效线索量 |
| 线索成交率 | 成交数 / 线上线索量 |
| 有效线索成交率 | 成交数 / 有效线索量 |
| 到店成交率 | 成交数 / 到店数 |

### 3.3 到店数特殊说明

本功能中面向使用者展示的「到店数」，不是客流明细原始记录条数，而是用于计算到店率和目标达成的核心口径。

```text
到店数 = 线上进店客流
```

去重规则：

- 同一线索
- 同一家门店
- 同一天
- 多次到店只算 1 次
- 不跨日去重
- 不全局去重

示例：

| 情况 | 到店数计算 |
| :--- | :--- |
| 同一线索同一门店同一天到店 3 次 | 算 1 |
| 同一线索同一门店连续两天各到店 1 次 | 算 2 |
| 同一线索不同门店同一天分别到店 | 分别按对应门店计算 |

### 3.4 有效线索口径

本功能的有效线索量只取：

```text
线索状态 = '跟进中'
```

该口径与其他已有报表可能存在差异，因此必须在本功能中独立计算。

### 3.5 成交口径

成交数据来自数据库中的线上实销表。

排除规则：

```text
四级渠道 != 'APP订单-排产定'
```

成交按线上实销记录统计，每条符合条件的记录代表一条成交。

## 四、目标体系

### 4.1 目标类型

本功能存在两套目标体系，分别用于不同管理目的。

| 目标类型 | 目的 | 是否合并 |
| :--- | :--- | :--- |
| 全国到店目标分解 | 判断全国到店目标及各门店分解进度 | 不合并 |
| 成交目标倒推到店 | 判断当前到店是否足以支撑成交任务 | 不合并 |

两类目标来源不同，计算逻辑不同，业务含义不同。页面中需要并列展示，避免合并成单一目标造成误判。

### 4.2 全国到店目标分解

#### 4.2.1 目标输入

按月份维护一个全国月度到店目标。

示例：

```text
2026-05 全国月度到店目标 = 50,000
```

该目标不是由门店目标汇总而来，而是一个全国总值。

#### 4.2.2 门店分解逻辑

按门店当月累计线上线索量占全国当月累计线上线索量的比例分解。

```text
门店线上线索占比 = 门店当月累计线上线索量 / 全国当月累计线上线索量

门店分解到店目标 = 全国月度到店目标 × 门店线上线索占比
```

说明：

- 分子和分母均只考虑线上线索。
- 线下线索始终不参与分解。
- 分子和分母均只考虑归属于当前门店表门店集合内的线索。
- 若线索归属门店不在当前门店表中，则该线索不进入全国当月累计线上线索量。
- 当月数据更新后，门店线索占比会随之变化，门店分解目标也会动态变化。

#### 4.2.3 时间进度与数据进度

本功能同时展示两个进度概念：

| 进度类型 | 计算方式 | 用途 |
| :--- | :--- | :--- |
| 时间进度 | 当前日期日序 / 当月自然日总数 | 展示自然月已过时间，帮助用户理解当前处于月内哪个阶段 |
| 数据进度 | 最新线上线索日期日序 / 当月自然日总数 | 用于全国到店目标达成、应达到店、缺口、预计月底等目标进度计算 |

```text
时间进度 = 当前日期日序 / 当月自然日总数

数据进度 = 当前数据库内最新线上线索日期日序 / 当月自然日总数
```

示例：

```text
当前日期为 5 月 17 日，则时间进度 = 17 / 31 = 54.8%
当前数据库内最新线上线索日期为 5 月 14 日，则数据进度 = 14 / 31 = 45.2%
```

不支持昨日维度。由于数据同步时间不固定，首页和专题页默认只看当月累计。

说明：

- 全国到店目标达成率、截至当前应达到店、到店目标缺口等目标进度类指标，使用数据进度计算。
- 时间进度仍在页面展示，用于提示真实自然月进展。
- 数据进度不使用客流进店时间推算。原因是当前上游客流进店时间标准化不足，可能出现异常未来日期，例如 2029 年进店时间。因此本功能以最新线上线索日期作为目标进度计算基准。
- 若最新线上线索日期不在所选月份内，则历史月份按 100%，未来月份按 0 或空状态处理。

#### 4.2.4 进度计算

```text
截至当前应达到店 = 门店分解到店目标 × 数据进度

到店目标达成率 = 实际到店数 / 截至当前应达到店

到店缺口 = 实际到店数 - 截至当前应达到店

预计月底到店 = 实际到店数 / 数据进度

预计月底达成率 = 预计月底到店 / 门店分解到店目标
```

### 4.3 成交目标倒推到店

#### 4.3.1 目标输入

成交目标按月份、门店、车型维护。

```text
成交目标粒度 = 月份 x 门店 x 车型
```

成交目标的线下来源通常为业务侧提供的「终端目标」表。为降低使用者理解门槛，系统内统一展示为「成交目标」。

需要注意：

- 终端目标表示线上及线下线索成交的总目标，不等同于线上实销表中的线上线索成交数。
- 本 PRD 中实际成交数仍来自线上实销表，代表线上线索成交。
- 目标倒推时，不单独设计「终端目标 -> 线上成交目标」的人为输入比例。
- 该比例与到店成交转化关系统一归入本节的转化率配置中，由使用者通过全国统一转化率或车型转化率进行管理。

#### 4.3.2 转化率配置

第一版采用「全国统一默认值 + 车型覆盖值」的设计。

| 配置层级 | 说明 | 优先级 |
| :--- | :--- | :--- |
| 车型转化率 | 针对某车型单独设置 | 高 |
| 全国统一转化率 | 默认使用的统一转化率 | 低 |

计算时优先使用车型转化率；若车型未配置，则使用全国统一转化率。

```text
使用转化率 = 车型转化率，如果存在；否则使用全国统一转化率
```

该转化率用于从成交目标倒推到店目标，可理解为综合倒推系数。它可以同时吸收：

- 终端目标中线上线索成交应承担的比例；
- 线上成交目标与到店数之间的转化关系；
- 业务管理中对不同车型目标难度的人工修正。

因此，第一版不再额外配置「终端目标转线上成交目标比例」。

后续可扩展为：

```text
门店车型 > 大区车型 > 全国车型 > 全国统一
```

#### 4.3.3 倒推计算

```text
成交倒推到店目标 = 车型成交目标 / 使用转化率

截至当前倒推应达到店 = 成交倒推到店目标 × 数据进度

倒推目标达成率 = 实际到店数 / 截至当前倒推应达到店

倒推到店缺口 = 实际到店数 - 截至当前倒推应达到店
```

### 4.4 历史趋势参考

当前阶段没有稳定的车型历史成交率可直接作为目标转化率，因此第一版以手动配置为准。

系统设计上需要预留历史趋势能力：

- 展示近 3 个月、近 6 个月的实际到店成交率。
- 展示全国、车型维度的历史线索成交率和到店成交率。
- 辅助判断当前手动转化率是否过高或过低。
- 后续支持基于历史趋势自动推荐转化率。

## 五、功能入口与信息架构

### 5.1 首页入口

本功能为高优先级功能，需要在首页主内容区直接展示基本数据。

位置：

```text
昨日数据 / 当月累计卡片下方
线索来源分布 / 到店数及到店率趋势上方
```

说明：

- 首页模块只展示当月累计数据。
- 不支持昨日切换。
- 点击模块进入专题页。

### 5.2 专题页入口

建议路由：

```text
/funnel-target-analysis
```

专题页默认进入区域负责人驾驶舱，而不是直接展示明细查询表。

专题页建议采用 Tab 或同页分区结构：

```text
驾驶舱 -> 明细分析 -> 配置中心
```

默认展示：

```text
驾驶舱
  顶部：核心进度与状态分布
  中部：大区 / 战区状态汇总
  底部：大区 x 门店列表
```

明细分析保留：

```text
门店 x 车型 -> 门店 x 车型 x 渠道
```

配置中心保留：

```text
全国到店目标配置
成交目标导入
成交倒推转化率配置
车型映射配置
重算
```

该结构优先服务区域负责人日常管理：先看范围内哪些门店落后，再对具体门店做车型和渠道原因分析。

## 六、首页模块设计

### 6.1 模块名称

```text
线上线索漏斗目标达成
```

### 6.2 模块目标

首页模块只回答一个问题：

```text
全国当前到店进度是否健康，哪里最需要关注？
```

### 6.3 展示内容

| 指标 | 说明 |
| :--- | :--- |
| 当月到店数 | 全国当月累计到店数 |
| 全国到店目标 | 当前配置的全国月度到店目标 |
| 全国到店目标达成率 | 实际到店数 / 截至当前应达到店 |
| 时间进度 | 当前日期日序 / 当月自然日总数 |
| 数据进度 | 最新线上线索日期日序 / 当月自然日总数 |
| 到店目标缺口 | 实际到店数 - 截至当前应达到店 |
| 成交倒推到店达成率 | 实际到店数 / 截至当前成交倒推应达到店 |
| 预计月底到店 | 基于当前时间进度推算 |
| 滞后大区数 | 达成率低于阈值的大区数量 |
| 缺口最大大区 Top 3 | 按到店目标缺口排序 |

### 6.4 配置提示

建议展示：

### 7.1.1 负责人视角 Tab

驾驶舱需要提供一个比普通筛选器更高频、更贴近日常工作的「负责人视角」切换能力。该能力用于区域负责人每天进入页面后，快速切换到自己或某个负责人的管理范围。

建议位置：

```text
全局筛选器下方
驾驶舱核心卡片上方
```

展示形式：

```text
负责人视角
[全部 494] [林若琦 38] [张玲 42] [王某 29] [更多负责人 ▼]
```

交互规则：

| 操作 | 结果 |
| :--- | :--- |
| 点击「全部」 | 清空负责人筛选，驾驶舱展示当前其他筛选条件下的全部门店 |
| 点击某个负责人 | 设置 `线索运营区域负责人 = 该负责人`，驾驶舱所有模块同步刷新 |

- 顶部核心状态卡；
- 门店进度状态分布；
- 大区 / 战区进度汇总；
- 大区 x 门店主表；
- 诊断标签分布；
- 后续从驾驶舱进入的门店 x 车型、门店 x 车型 x 渠道明细。

第一版负责人视角采用门店表字段：

```text
线索运营区域负责人
```

即技术字段：

```text
lead_ops_owner
```

第一版暂不做「我的负责范围」自动识别。后续在账号与负责人映射关系明确后，可根据登录账号默认选中对应负责人；总部账号默认「全部」。

若负责人数量较多，第一版建议展示：

- 全部；
- 按门店数或业务配置排序的前 8 个负责人；
- 更多负责人下拉搜索。

### 7.2 第一部分：区域负责人驾驶舱

#### 7.2.1 目标

驾驶舱是专题页默认首屏，面向区域负责人和区域支持，目标是在每天数据同步后快速回答：

```text
我负责范围内，当前哪些门店进度健康，哪些门店落后，落后门店大概是什么原因？
```

驾驶舱第一版不做复杂图表，采用简洁可视化：

- 核心状态卡
- 状态分布条
- 大区 / 战区汇总列表
- 大区 x 门店主表
- 诊断标签

#### 7.2.2 顶部核心卡片

| 卡片 | 内容 | 点击联动 |
| :--- | :--- | :--- |
| 管理门店数 | 当前筛选范围内门店数 | 清除状态筛选，展示全部门店 |
| 当月到店数 | 当前范围当月累计到店数 | 展示全部门店并按到店数降序 |
| 到店目标达成率 | 实际到店数 / 截至当前应达到店 | 展示落后门店 |
| 倒推达成率 | 实际到店数 / 截至当前成交倒推应达到店 | 展示倒推落后门店 |
| 严重落后门店数 | 状态 = 严重落后的门店数量 | 下方门店列表仅展示严重落后门店 |
| 轻度落后门店数 | 状态 = 轻度落后的门店数量 | 下方门店列表仅展示轻度落后门店 |
| 配置异常门店数 | 缺目标、缺转化率或关键车型未映射门店数 | 下方门店列表仅展示配置异常门店 |

说明：

- 顶部卡片点击后不跳转页面，仅刷新同页下方「大区 x 门店」列表。
- 卡片需要展示当前已选筛选条件，避免用户误以为看到的是全国。

#### 7.2.3 门店进度状态定义

门店状态以「目标达成率」对比「数据进度」判断。数据进度使用最新线上线索日期，不使用客流进店时间。

```text
进度差值 = 到店目标达成率 - 数据进度
```

建议状态：

| 状态 | 判断规则 | 说明 |
| :--- | :--- | :--- |
| 领先 | 进度差值 >= 5pct | 明显快于当前数据进度 |
| 正常 | -5pct <= 进度差值 < 5pct | 基本匹配当前数据进度 |
| 轻度落后 | -15pct <= 进度差值 < -5pct | 需要关注 |
| 严重落后 | 进度差值 < -15pct | 需要优先管理 |
| 配置异常 | 缺目标、缺转化率、关键映射缺失等 | 需要先补配置或确认口径 |

若后续业务希望收紧或放宽阈值，可将 `5pct` 和 `15pct` 设计为配置项。

#### 7.2.4 状态分布

展示当前筛选范围内各状态门店数量和占比。

示例：

```text
领先 12 家 | 正常 80 家 | 轻度落后 25 家 | 严重落后 10 家 | 配置异常 3 家
```

交互：

- 点击任一状态后，下方门店列表按该状态过滤。
- 状态筛选应在页面上可见，并支持一键清除。

#### 7.2.5 大区 / 战区汇总

用于回答「哪个区域问题最大」。

第一版建议按大区展示，可支持切换到战区。

字段：

| 字段 | 说明 |
| :--- | :--- |
| 大区 / 战区 | 组织归属 |
| 门店数 | 当前范围门店数量 |
| 到店数 | 当前范围累计到店 |
| 到店目标 | 分解后的目标汇总 |
| 到店目标达成率 | 实际到店 / 截至当前应达到店 |
| 倒推达成率 | 实际到店 / 截至当前倒推应达到店 |
| 轻度落后门店数 | 状态门店数量 |
| 严重落后门店数 | 状态门店数量 |
| 目标缺口 | 实际到店 - 截至当前应达到店 |

交互：

- 点击大区后，下方门店列表仅展示该大区门店。
- 点击战区后，下方门店列表仅展示该战区门店。
- 大区和战区对应关系直接来自门店表。

#### 7.2.7 初步诊断标签

第一版诊断标签以规则判断为主，不做复杂模型。

| 诊断标签 | 判断方向 |
| :--- | :--- |
| 线索不足 | 门店线上线索占比低于目标分解需要，或低于同区域均值 |
| 有效率低 | 线索有效率低于全国或同区域均值 |
| 到店转化低 | 线索到店率低于全国或同区域均值 |
| 倒推压力高 | 成交目标倒推应达到店显著高于全国到店目标分解应达到店 |
| 车型结构异常 | 有成交目标车型到店明显不足，或实际车型与目标车型不匹配 |
| 渠道结构异常 | 主要渠道线索量、有效率或到店率明显偏低 |
| 配置异常 | 成交目标、转化率或关键车型映射缺失 |

第一版可先输出 1-2 个优先级最高的标签，后续再丰富规则。

#### 8.2.1 成交目标 Excel 导入规则

业务侧提供的目标文件可能以「终端目标」命名，系统导入后统一转换为「成交目标」。

样例文件结构参考项目根目录：

```text
终端目标样例.xlsx
```

样例中工作表为多层表头结构：

- 基础字段：大区、序号、省份、城市、店编号、主体代码、店简称。
- 目标字段：合计、VH、i60、RT、UT、N60 等车型块。
- 每个目标块中可能包含提车、订单、终端等字段。
- 部分车型存在多个子车型，因此会出现「终端小计」字段，表示大车型汇总终端目标。

导入时仅关注：

| 来源字段 | 导入含义 |
| :--- | :--- |
| 店编号 | 与当前门店表匹配的门店编码 |
| 店简称 | 辅助展示，不作为唯一匹配依据 |
| 合计 - 终端目标 | 门店总成交目标 |
| 车型 - 终端 | 单一车型成交目标 |
| 车型 - 终端小计 | 大车型成交目标，用于存在子车型拆分的车型 |

不关注：

- 提车目标
- 订单目标
- 提车小计
- 订单小计
- 子车型终端明细，除非后续需要支持子车型分析

车型目标取值规则：

| 场景 | 取值方式 |
| :--- | :--- |
| 车型只有「终端」字段 | 取该车型「终端」 |
| 车型存在「终端小计」字段 | 优先取「终端小计」作为大车型成交目标 |
| 车型存在多个子车型终端字段 | 第一版不按子车型拆分，使用「终端小计」 |
| 合计目标 | 取「合计 - 终端目标」作为门店总成交目标 |

导入后的目标粒度：

```text
月份 x 门店 x 车型
```

同时建议保存门店总成交目标，用于校验各车型成交目标之和是否与门店合计一致。

#### 8.2.2 门店范围过滤规则

成交目标文件中的门店数量可能超过当前门店表中的门店数量。本功能以当前门店表为管理边界。

导入规则：

- 若目标文件中的店编号存在于当前门店表，则导入该门店目标。
- 若目标文件中的店编号不存在于当前门店表，则跳过该门店目标。
- 跳过门店不参与成交目标、倒推到店目标、达成率和缺口计算。
- 导入完成后建议展示导入结果摘要。

导入结果摘要建议包括：

| 摘要项 | 说明 |
| :--- | :--- |
| 文件门店数 | Excel 中识别到的门店数量 |
| 成功匹配门店数 | 存在于当前门店表并成功导入的门店数量 |
| 跳过门店数 | 不存在于当前门店表的门店数量 |
| 成功导入车型目标数 | 成功生成的门店 x 车型目标记录数 |
| 异常记录数 | 空店编号、目标非数字、重复门店等异常 |

### 8.4 车型映射配置

车型映射是本功能的正式配置能力，用于解决线索车型、到店车型、成交车型、成交目标车型命名不一致的问题。

配置页面不要求运营人员先提供一份外部全量映射表，而是由系统自动扫描当前源数据中真实存在的车型值，生成待维护清单。运营人员在页面上看到当前数据中有哪些原始车型值、各自影响多少数据，再进行逐条或批量映射。

#### 8.4.1 源车型扫描范围

系统需从以下来源扫描原始车型值：

| 来源类型 | 来源数据 | 原始车型字段 | 参与指标 |
| :--- | :--- | :--- | :--- |
| 线索 | 线索表 / DuckDB 线索集市表 | 当前漏斗计算使用的线索意向车型字段 | 线上线索量、有效线索量 |
| 到店 | 客流明细 / 跟进相关字段 | 当前为意向车系编码，后续可切换为转译后的车型名 | 到店记录数、到店数 |
| 成交 | 线上实销表 | 实销车系、邀约后意向车系、原始意向车系等当前成交计算使用字段 | 成交数 |
| 成交目标 | 成交目标 Excel 导入结果 | Excel 表头车型，如 i60、RT、N60、UT、VH | 成交目标、成交倒推到店 |

#### 8.4.2 源车型扫描表

建议新增源车型扫描结果表，用于页面展示和维护优先级判断。

| 字段 | 说明 |
| :--- | :--- |
| 月份 | 数据所属月份 |
| 来源类型 | 线索 / 到店 / 成交 / 成交目标 |
| 来源字段 | 原始车型值来自哪个字段 |
| 原始车型值 | 源数据中真实出现的车型值或编码 |
| 出现次数 | 该原始值在对应来源中的记录数 |
| 影响门店数 | 涉及多少门店 |
| 指标数量 | 线索数 / 到店数 / 成交数 / 目标数，按来源含义展示 |
| 当前标准车型 | 已配置的标准车型名称 |
| 映射状态 | 已映射 / 未映射 / 停用 |
| 是否参与目标倒推 | 是 / 否 |
| 最近发现时间 | 最近一次扫描发现该值的时间 |

#### 8.4.3 映射配置表

建议将现有 `funnel_model_mapping` 扩展为以下语义：

| 字段 | 说明 |
| :--- | :--- |
| 来源类型 | 线索 / 到店 / 成交 / 成交目标 |
| 来源字段 | 原始车型值所在字段 |
| 原始车型值 | 源数据中的原始值 |
| 标准车型名称 | 漏斗分析统一使用的车型名称 |
| 是否参与目标倒推 | 控制该标准车型是否可用于成交目标倒推 |
| 是否启用 | 启用 / 停用 |
| 更新人 | 最近更新用户 |
| 更新时间 | 最近更新时间 |

同一来源类型、来源字段、原始车型值，在启用状态下只能映射到一个标准车型。

#### 8.4.4 映射计算规则

所有来源数据进入漏斗计算前，均执行车型标准化：

```text
来源类型 + 来源字段 + 原始车型值 -> 标准车型名称
```

若存在启用映射：

```text
车型 = 标准车型名称
unmapped_model_flag = false
```

若不存在启用映射：

```text
车型 = 原始车型值
unmapped_model_flag = true
```

未映射数据不得被丢弃。它仍然参与：

- 全国实际线上线索量、有效线索量、到店数、成交数；
- 大区、门店、车型、渠道实际分析；
- 未映射车型清单和影响范围提示。

但未映射数据不参与成交目标倒推。

#### 8.4.5 目标车型与实际车型不一致的处理

成交目标车型和实际车型必须通过映射归集到同一标准车型后，才能在门店 x 车型表中同一行展示目标和实际指标。

示例：

| 来源 | 原始车型值 | 标准车型 |
| :--- | :--- | :--- |
| 成交目标 | i60 | AION i60 |
| 线索 | AION i60 | AION i60 |
| 到店 | AAY7 | AION Y Plus |
| 成交目标 | RT | AION RT |

若成交目标只有 5 款车型，但实际线索和到店存在 7 款车型，则：

- 7 款车型的实际线上线索、有效线索、到店、成交均进入总量；
- 有成交目标且映射到标准车型的 5 款车型参与成交目标倒推；
- 多出的 2 款车型在门店 x 车型表中展示实际指标，但成交目标和倒推指标为空或 0，并标记为「无成交目标」；
- 多出的 2 款车型不得与其他目标车型交叉合并。

#### 8.4.6 客流车型后续转译兼容

当前到店来源可能仍使用车系编码，例如 `AAY7`。后续业务侧会补充客流车型转译，使其变为可与标准车型匹配的名称。

本功能需兼容两种情况：

1. 若客流原始字段仍是编码，则配置 `到店 / 意向车系编码 / AAY7 -> 标准车型`。
2. 若后续新增了转译后的车型名称字段，则源车型扫描改为扫描新字段，并生成新的待映射源值。

因此，车型映射配置必须保留 `来源类型 + 来源字段 + 原始车型值`，不能只按车型名称做全局简单映射。

#### 8.4.7 页面交互要求

车型映射配置页面需支持：

- 按来源类型筛选：线索、到店、成交、成交目标。
- 按映射状态筛选：全部、未映射、已映射、停用。
- 展示每个原始车型值的出现次数、影响门店数、影响指标数量。
- 支持单条编辑标准车型。
- 支持批量将多个原始值映射到同一标准车型。
- 保存映射后提示需要重算当前月份。
- 页面顶部展示未映射影响摘要，例如：

```text
当前存在 12 个未映射车型值，涉及线上线索 3,245、到店 128、成交 6、成交目标 0。
```

## 十二、非功能要求

### 12.1 性能

- 首页模块加载应与首页其他数据保持一致，避免明显拖慢首页。

- 数据同步后，需要重新计算本功能独立指标表。
- 目标或转化率配置调整后，需要重新计算相关目标字段。
- 车型映射调整后，需要支持重新刷新车型归因结果。

### 12.3 可解释性

页面中需要明确展示关键口径：

- 仅统计线上线索。
- 有效线索 = 线索状态为跟进中。
- 到店数 = 线上进店客流，不跨日去重。
- 成交排除四级渠道为 APP订单-排产定。
- 时间进度按自然日展示。
- 目标达成、应达到店、缺口和预计月底使用最新线上线索日期对应的数据进度计算。
- 车型映射按源数据自动扫描出的原始车型值维护，未映射数据不丢弃。

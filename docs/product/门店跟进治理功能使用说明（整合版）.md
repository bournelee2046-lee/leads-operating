## 2. 功能定位

门店跟进治理功能用于在线索运营过程中识别、查看、跟进和复盘异常门店。系统基于现有日报数据、日/周任务、跟进记录、门店档案和门店管理能力，形成以下治理闭环：

1. 基于日报数据查看门店线索量、到店数、到店率等指标。
2. 通过人工筛选方式确定需要治理的异常门店。
3. 在日任务或周任务中查看门店快照、跟进记录和连续上榜情况。
4. 对门店填写跟进原因、备注、操作人和跟进时间。
5. 通过 AI 生成日总结或周总结，并由人工确认后沉淀入库。
6. 从任务链路跳转到现有门店档案和门店管理页面进行复盘与维护。

## 3. 功能入口

### 3.1 首页入口

登录线索运营监控系统后，进入首页，在“功能导航”区域点击 **异常门店治理**。

对应路由：

```text
/follow-up
```

本地开发环境常用登录地址：

```text
http://localhost:5176/login
```

### 3.2 关联入口

| 功能 | 路由 | 说明 |
|---|---|---|
| 异常门店治理 | `/follow-up` | 查看异常任务、连续上榜和门店快照 |
| 跟进记录 | `/follow-up/distribution` | 复用现有跟进记录能力 |
| 门店档案 | `/store_profile`、`/store_detail/:store_code` | 复用现有门店档案能力 |
| 门店管理 | `/store_management` | 复用现有门店状态、评级和备注维护能力 |

如历史环境仍保留 `/follow_up`，仅作为兼容入口或旧版页面入口，不作为本次新治理页面的主入口。

## 5. 数据来源与复用边界

本功能不重新建设日报导入、任务底座、门店档案和门店管理，仅复用现有能力。

| 能力 | 处理方式 |
|---|---|
| 日报导入 | 复用现有线索运营监控系统日报导入、预检查、新增和更新能力 |
| 日报数据 | 复用现有 `日报快照` 等日报数据作为筛选、趋势和基准来源 |
| 日/周任务 | 复用现有任务数据和任务状态，作为治理页面展示基础 |
| 跟进记录 | 复用现有跟进记录表和跟进原因配置 |
| 门店档案 | 复用现有门店档案页面和数据，不新增前端建设项 |
| 门店管理 | 复用现有门店状态、评级、备注维护能力，不新增前端建设项 |
| 权限与日志 | 复用现有账号权限、登录日志和操作日志体系 |

## 6. 已确认业务口径

1. 异常门店筛选规则以人工筛选为主，暂不固化为系统自动规则。
2. 连续上榜判定仅基于当前人工筛选条件，不单独配置异常规则。
3. AI 总结生成后必须由人工确认，确认后才写入任务总结或历史记录。
4. 日任务和周任务允许同一门店在同一周期内重复进入多个任务。
5. 环比下降默认比较指标为 **到店数**。
6. 环比下降筛选需要配置下降比例阈值，只有下降超过指定比例的门店才纳入筛选结果。

## 7. 核心指标说明

| 指标 | 说明 |
|---|---|
| 线索量-本地 | 门店本地线索量 |
| 到店数 | 门店到店数量，环比下降筛选默认使用该指标 |
| 到店率 | 到店数 / 线索量-本地，页面按百分比展示 |
| 环比上周下降 | 当前周期到店数与上周同期对比，下降超过阈值时纳入筛选 |
| 环比上月同期下降 | 当前周期到店数与上月同期对比，下降超过阈值时纳入筛选 |
| 连续上榜天数 | 门店连续满足当前人工筛选条件的天数 |

## 8. 主要功能说明

### 8.1 任务总览

进入异常门店治理页面后，页面展示任务总览信息，通常包括：

- 任务总数。
- 进行中任务数。
- 已完成任务数。
- 已归档任务数。
- 涉及门店数。
- 最近任务创建或更新时间。

运营人员可通过任务列表查看日任务、周任务、任务状态、基准日期、门店数量、跟进数量和最近操作记录。

### 8.2 任务筛选

任务列表支持按以下条件查看：

- 任务状态：进行中、已完成、已归档。
- 任务维度：日任务、周任务。
- 关键词：任务名称、门店信息等。

筛选后，点击目标任务可查看任务内门店快照和跟进详情。

### 8.3 门店筛选条件

门店筛选以人工操作为主。常用筛选条件包括：

- 线索量-本地。
- 到店数。
- 到店率。
- 环比上周下降。
- 环比上月同期下降。
- 连续上榜天数。

环比下降筛选默认比较 `到店数`，并需要设置下降比例阈值。例如阈值设置为 `10%` 时，只有到店数较对比周期下降超过 10% 的门店才进入筛选结果。

### 8.4 连续上榜

页面会展示门店连续上榜情况，展示格式为：

```text
连续上榜 X 天
```

计算规则：

1. 仅基于当前人工筛选条件计算。
2. 门店在连续日报日期中均满足筛选条件时，连续天数累加。
3. 某日不满足条件或无有效日报数据时，连续上榜中断。
4. 任务保存时应保留当次计算快照，避免后续规则变化影响历史复盘。

连续上榜门店应优先关注，并在日总结、周总结中重点体现。

### 8.5 门店快照

任务详情中展示任务内门店快照，通常包括：

- 店编号。
- 店简称。
- 大区、战区。
- 门店状态。
- 治理状态。
- 门店评级。
- 线索量-本地。
- 到店数。
- 到店率。
- 环比上周变化。
- 环比上月同期变化。
- 连续上榜天数。
- 最新跟进记录。

门店快照用于还原任务创建或筛选时的门店状态，历史任务查看时以快照为准。

### 8.6 跟进记录

运营人员可对任务内门店填写或查看跟进记录。

跟进记录内容包括：

- 跟进原因。
- 备注。
- 操作人。
- 实际跟进时间。
- 关联任务。
- 关联日报日期。

跟进原因配置复用现有能力，常见原因包括：

- 线索量正常，无需干预。
- 线索量下降，已联系督导。
- 线索量下降，已联系店长。
- 线索量下降，等待自然恢复。
- 门店积极配合，等待数据回升。
- 门店不配合，已上报。
- 到店率正常。
- 到店率偏低，已提醒门店。
- 到店率偏低，门店已采取措施。
- 其他原因。

### 8.7 AI 总结

日任务或周任务结束后，系统可调用 AI 生成总结。

AI 总结必须经过人工确认后才入库。用户可以在确认前编辑总结内容。

日总结建议包含：

- 当日筛选门店数量。
- 已跟进门店数量和未跟进门店数量。
- 主要异常原因。
- 连续上榜门店。
- 待继续跟进事项。

周总结建议包含：

- 本周异常门店整体变化。
- 连续上榜门店清单或 TopN。
- 跟进完成情况。
- 跟进原因分布。
- 本周结论和下周建议。

AI 总结调用失败时，不影响任务完结，用户可手动填写总结。

### 8.8 门店档案跳转

任务门店列表中可跳转到现有门店档案页面，查看单店复盘信息，包括：

- 门店基础信息。
- 日报趋势。
- 历史跟进记录。
- 跟进原因分布。
- 单店治理过程。

门店档案能力复用现有页面和数据，不在本功能内重复建设。

### 8.9 门店管理跳转

具备门店管理权限的用户，可从治理链路进入现有门店管理页面，维护：

- 治理状态。
- 门店评级。
- 状态备注。
- 管理员备注。

门店管理仍受 `store_management` 权限控制。

## 9. 典型工作流程

### 9.1 每日治理流程

1. 通过现有日报导入能力导入最新日报。
2. 进入首页“功能导航”，点击“异常门店治理”。
3. 查看日任务或按日期查看门店指标。
4. 根据线索量、到店数、到店率、环比下降等条件人工筛选异常门店。
5. 重点查看连续上榜门店。
6. 对异常门店填写跟进原因和备注。
7. 日任务结束后生成 AI 日总结。
8. 人工编辑、确认总结后保存。

### 9.2 每周治理流程

1. 周一查看或创建本周跟进任务。
2. 系统使用上周日作为周任务默认基准日期。
3. 若基准数据缺失，先通过现有日报导入能力补充日报。
4. 按周查看门店线索量、到店数、到店率和环比下降情况。
5. 识别连续上榜门店，安排重点跟进。
6. 周一至周四持续补充跟进记录。
7. 周五或周期结束时生成周统计报告和 AI 周总结。
8. 人工确认总结后完结任务，进入历史复盘。

### 9.3 历史复盘流程

1. 在异常门店治理页面查看历史任务。
2. 按任务状态、日/周维度或关键词筛选。
3. 查看任务门店快照、跟进记录和任务历史。
4. 查看 AI 总结和人工确认内容。
5. 跳转门店档案查看单店长期趋势和历史原因分布。
6. 如需维护长期治理状态，进入门店管理页面更新门店状态、评级或备注。

## 10. 任务状态说明

| 状态 | 说明 |
|---|---|
| 进行中 | 任务正在跟进，可继续补充记录 |
| 已完成 | 当前周期治理已完成，可查看总结和历史 |
| 已归档 | 任务已从常规列表移除，但可在历史中查看和恢复 |

删除任务时应使用软删除方式，即将任务状态变为 `已归档`，不直接物理删除历史数据。

## 11. 异常与提示

| 场景 | 处理方式 |
|---|---|
| 缺少日报数据 | 提示先通过现有日报导入入口补充数据 |
| 周任务缺少上周日基准数据 | 阻止创建或提示补充对应日期日报 |
| 查询日期范围无数据 | 提示未找到指定范围内的数据 |
| AI 总结调用失败 | 保留任务状态操作，提示用户手动填写总结 |
| 用户无权限 | 隐藏入口或跳转无权限页面 |
| 归档任务恢复 | 恢复到可查看状态，并记录恢复操作 |

## 12. 使用注意事项

1. 本功能使用现有日报数据，请先确认日报已导入且日期完整。
2. 环比下降筛选默认比较到店数，筛选前需确认下降阈值是否符合本次治理目标。
3. 连续上榜结果依赖当前人工筛选条件，不代表系统固化异常规则。
4. AI 总结仅作为辅助，必须人工确认后才保存。
5. 门店档案和门店管理是复用现有能力，如入口不可见，请检查账号权限。
6. 历史任务应以任务快照为准，避免后续日报更新或规则调整影响复盘口径。

## 13. 数据对象说明

| 数据对象 | 说明 |
|---|---|
| 日报快照 | 复用现有日报数据，作为指标筛选、趋势分析和基准数据来源 |
| 跟进任务 | 复用现有任务数据，以日/周为单位组织治理范围 |
| 跟进记录 | 保存单店跟进原因、备注、操作人和跟进时间 |
| 跟进原因配置 | 维护可选跟进原因 |
| 任务总结 | 保存日总结、周总结、AI 总结和人工确认内容 |
| 任务历史 | 保存任务状态流转、归档恢复和人工调整记录 |
| 门店管理配置 | 保存治理状态、门店评级、状态备注和管理员备注 |
| 用户与权限 | 控制页面入口和操作范围 |
| 操作日志 | 记录关键操作人、时间和内容 |

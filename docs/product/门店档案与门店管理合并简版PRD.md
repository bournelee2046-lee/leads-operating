# 门店档案与门店管理合并简版 PRD

## 1. 背景

当前「异常店治理工具」中已沉淀了日报导入、跟进任务、跟进记录、门店档案、门店管理等能力。后续计划将其中与门店治理相关的功能逐步合并到「线索运营监控系统」中。

本阶段优先迁移：

- 门店档案
- 门店详情
- 门店管理

目标是从当前以「跟进任务」为中心的使用方式，逐步沉淀为以「门店」为中心的治理档案。

## 2. 功能入口

功能入口放在「经销商管理」页面下。

现有入口：

- 运营日报
- 逾期查询

新增入口：

- 门店档案
- 门店管理

对应页面：

- `/store_profile`：门店档案
- `/store_detail/<store_code>`：门店详情
- `/store_management`：门店管理

## 3. 数据口径

### 3.1 门店基础信息

门店基础信息来自 `leads.db`，作为基础源数据。

主要包括：

- 店编号
- 店简称
- 大区
- 战区
- 大区经理
- 战区经理
- 巡回员
- 门店状态

说明：

- `leads.db` 只作为基础门店信息来源。
- 系统不在本功能中回写 `leads.db`。
- `leads.db` 中的「门店状态」保留为源表状态，只读展示。

### 3.2 日报趋势

门店档案中的日报趋势沿用异常店治理工具现有口径。

数据来源：

- `日报.db`
- `日报快照` 表

展示指标：

- 线索量-本地
- 到店数
- 到店率

到店率计算：

```text
到店率 = 到店数 / 线索量-本地
```

说明：

- 第一阶段不切换为线索运营监控系统中的运营日报口径。
- 保持当前异常店治理工具中的日报趋势逻辑，避免治理人员看到的数据口径发生变化。

### 3.3 治理信息

治理过程中的人工维护信息存储在系统治理表中，不写入 `leads.db`。

治理信息包括：

- 治理状态
- 门店评级
- 状态备注
- 管理员备注
- 跟进任务
- 跟进记录
- 跟进原因

字段区分：

| 字段 | 来源 | 说明 |
|---|---|---|
| 门店状态 | `leads.db` | 源表门店状态，只读展示 |
| 治理状态 | 治理系统表 | 人工维护，代表当前治理判断 |
| 门店评级 | 治理系统表 | 人工维护，代表运营评级 |
| 状态备注 | 治理系统表 | 对治理状态的补充说明 |
| 管理员备注 | 治理系统表 | 运营管理备注 |

## 4. 页面说明

### 4.1 门店档案

页面定位：

用于从门店维度查看治理情况，辅助识别长期问题门店。

主要功能：

- 门店搜索：按店编号、店简称搜索。
- 条件筛选：大区、战区、门店状态、治理状态、是否跟进过。
- 门店列表：展示门店基础信息、治理状态、评级、跟进次数、最近跟进时间。
- 高频问题店：识别多次被跟进的门店。
- 原因分析：查看跟进原因分布。
- 跳转门店详情：进入单店完整档案。

页面主要用于查看和分析，不作为批量维护入口。

### 4.2 门店详情

页面定位：

用于查看单家门店的完整治理档案。

主要模块：

1. 基础信息
   - 来自 `leads.db`
   - 只读展示

2. 治理信息
   - 治理状态
   - 门店评级
   - 状态备注
   - 管理员备注
   - 支持单店编辑

3. 日报趋势
   - 来自 `日报快照`
   - 展示线索量-本地、到店数、到店率
   - 支持近 7 天、近 30 天、自定义日期

4. 跟进历史
   - 展示该门店历史跟进记录
   - 包含任务周次、跟进原因、备注、操作人、跟进时间

5. 原因分析
   - 汇总该门店历史跟进原因
   - 辅助判断是否为长期问题店

### 4.3 门店管理

页面定位：

用于集中维护门店治理信息。

主要功能：

- 查看所有门店。
- 按大区、战区、门店状态、治理状态、评级筛选。
- 搜索店编号、店简称。
- 编辑单店治理状态。
- 编辑门店评级。
- 编辑状态备注、管理员备注。
- 配置治理状态选项。
- 配置评级选项。

说明：

- 门店管理维护的是治理系统自己的信息。
- 页面中的「门店状态」为源表状态，只读。
- 页面中的「治理状态」为系统维护状态，可编辑。

## 5. 高频问题店识别

系统需要识别多次被跟进的门店，辅助定位长期问题店。

基础规则：

- 默认跟进次数大于等于 3 次的门店，识别为高频跟进门店。

展示字段：

- 店编号
- 店简称
- 大区
- 战区
- 治理状态
- 门店评级
- 跟进次数
- 首次跟进时间
- 最近跟进时间
- 跟进原因汇总

后续可扩展规则：

- 最近 30 天内多次跟进。
- 同一原因重复出现。
- 到店率持续下降。
- 治理状态长期未恢复。

## 6. 权限控制

新增权限：

- 门店档案查看权限
- 门店详情查看权限
- 门店管理查看权限
- 治理信息编辑权限
- 治理状态/评级配置权限

权限效果：

- 无门店档案权限：不可访问门店档案和门店详情。
- 无门店管理权限：不可访问门店管理。
- 无编辑权限：只能查看治理信息，不能修改治理状态、评级和备注。
- 无配置权限：不能新增、编辑、删除治理状态和评级配置。

## 7. 典型使用流程

### 7.1 日常治理

1. 用户导入日报快照。
2. 用户在跟进治理中创建周任务。
3. 用户选择需要治理的门店。
4. 用户每日填写跟进原因和备注。
5. 系统自动把跟进记录沉淀到门店档案。
6. 用户在门店档案中查看门店历史趋势和跟进历史。
7. 对长期异常门店，在门店管理中维护治理状态、评级和备注。

### 7.2 查看长期问题店

1. 进入门店档案。
2. 切换到高频问题店视图。
3. 查看多次被跟进门店。
4. 进入门店详情。
5. 查看日报趋势、跟进历史和原因分析。
6. 根据实际情况维护治理状态。

## 8. 本阶段不做

本阶段不做以下内容：

- 不停止异常店治理工具现有服务。
- 不删除异常店治理工具现有功能。
- 不回写 `leads.db`。
- 不替换日报趋势口径。
- 不强制迁移日报导入、跟进任务创建等完整治理流程。
- 治理状态、评级、备注仅作为门店治理管理信息，不参与任何现有指标计算、筛选剔除或考核口径。

说明：

- 例如后续如需定义「治理状态 = 摆烂，不参与全部计算」或「治理状态 = 钉子户，不参与某个环节计算」，需要单独设计规则配置，并经业务确认后再接入对应计算模块。
- 在本阶段完成前，新增治理信息不会影响现有运营日报、逾期查询、漏斗目标、首页看板等已有功能。

## 9. 验收标准

- 经销商管理页新增「门店档案」「门店管理」入口。
- 门店档案可搜索、筛选门店。
- 门店详情可展示基础信息、日报趋势、跟进历史、原因分析。
- 日报趋势口径与异常店治理工具一致。
- 门店管理可维护治理状态、评级、状态备注、管理员备注。
- 页面明确区分「门店状态」和「治理状态」。
- 治理状态优先使用系统内维护结果。
- 无权限用户不能访问或编辑相关功能。

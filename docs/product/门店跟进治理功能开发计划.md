## 3. 开发原则

1. 不重做日报导入，继续复用现有日报数据和导入入口。
2. 不迁移现有跟进记录底座，继续复用现有跟进任务、跟进记录和原因配置。
3. 不重做门店档案和门店管理前端，只在治理链路中提供跳转和数据复用。
4. 异常门店筛选以人工筛选为主，不固化为独立系统规则。
5. 连续上榜仅基于当前筛选条件计算。
6. 环比下降默认比较指标为 `到店数`，并支持下降比例阈值。
7. AI 总结必须人工确认后才入库。
8. 所有关键写操作必须有权限校验和操作日志。

## 4. 阶段计划

## Phase 1：治理数据模型与 API 补齐

目标：补齐任务创建、任务状态流转、任务总结和筛选快照需要的后端能力。

### 4.1 数据结构调整

在现有治理库中扩展轻量字段或表，不影响现有日报、门店档案和门店管理能力。

建议新增或确认以下结构：

| 对象 | 字段/表 | 说明 |
|---|---|---|
| 跟进任务 | `任务维度` | 区分日任务、周任务 |
| 跟进任务 | `筛选日期` | 日任务关联日报日期 |
| 跟进任务 | `筛选条件` | JSON 保存人工筛选条件和阈值 |
| 跟进任务 | `门店快照` | JSON 保存当次入选门店指标快照 |
| 跟进任务 | `归档时间`、`归档人` | 支持软删除和恢复 |
| 任务总结 | 新表 | 保存日/周总结、AI 总结、人工确认内容 |
| 任务历史记录表 | 扩展使用 | 保存创建、完成、归档、恢复、总结确认等操作 |

### 4.2 后端 API

| API | 方法 | 说明 |
|---|---|---|
| `/api/governance/overview` | GET | 已有，继续完善筛选和分页 |
| `/api/governance/tasks` | GET | 已有，任务列表查询 |
| `/api/governance/tasks` | POST | 新增日任务/周任务 |

### 4.3 后端验收点

- 可创建日任务和周任务。
- 可按筛选条件预览门店，支持线索量、到店数、到店率、环比上周下降、环比上月同期下降。
- 环比下降默认使用到店数，并按阈值筛选。
- 可保存任务门店快照。
- 可完成、归档、恢复任务。
- 可写入任务历史和操作日志。
- AI 总结失败不影响任务状态操作。

## Phase 2：异常门店治理前端完善

目标：把 `/follow-up` 从展示型页面补齐为可操作的治理工作台。

### 4.4 页面结构

页面建议拆成以下区域：

1. 顶部概览：任务总数、进行中、已完成、已归档、任务门店总览。
2. 任务筛选区：状态、日/周维度、关键词、日期。
3. 任务列表：展示任务维度、状态、门店数、跟进数、基准日期、创建时间。
4. 任务详情：展示任务基本信息、状态操作、总结状态。
5. 门店筛选与快照：展示指标、环比、连续上榜、筛选阈值和排序。
6. 跟进记录：展示和编辑门店跟进原因、备注。
7. 任务历史：展示状态流转、归档恢复、总结确认等记录。
8. 复用入口：门店档案、门店管理、跟进记录。

### 4.5 前端功能

| 功能 | 说明 |
|---|---|
| 新建任务弹窗 | 选择日任务/周任务、筛选日期/周开始日期、基准日期 |
| 筛选条件面板 | 支持指标筛选、环比下降筛选、阈值设置 |
| 门店预览 | 保存前预览入选门店，支持勾选/取消 |
| 保存门店快照 | 将人工确认后的门店列表保存到任务 |
| 门店跟进编辑 | 选择跟进原因、填写备注并保存 |
| 状态操作按钮 | 完成、归档、恢复，带二次确认 |
| AI 总结弹窗 | 生成总结、编辑总结、人工确认保存 |
| 权限态 | 无权限时隐藏操作按钮或展示只读状态 |
| 错误提示 | 无日报、无基准数据、AI 失败、保存失败时明确提示 |

### 4.6 前端验收点

- 首页入口可见并可进入治理页面。
- 管理员可创建任务、筛选门店、保存快照。
- 可对单店填写跟进原因和备注。
- 任务详情能展示连续上榜、环比上周、环比上月。
- 任务可完成、归档、恢复。
- AI 总结可生成草稿，人工确认后可在任务历史中查看。
- 门店档案和门店管理跳转不破坏现有页面。

## Phase 3：AI 总结与历史复盘

目标：形成日/周任务总结和历史复盘闭环。

### 4.7 AI 总结流程

1. 用户点击“生成总结”。
2. 后端汇总任务门店、跟进记录、连续上榜门店、主要原因分布。
3. 调用 AI 服务生成总结草稿。
4. 前端展示总结草稿，允许用户编辑。
5. 用户点击“确认保存”。
6. 后端保存总结，记录确认人、确认时间、总结来源。
7. 写入任务历史和操作日志。

### 4.8 总结内容模板

日总结：

- 当日筛选门店数量。
- 已跟进和未跟进门店数量。
- 主要异常原因。
- 连续上榜门店。
- 次日继续跟进事项。

周总结：

- 本周异常门店整体变化。
- 连续上榜门店 TopN。
- 跟进完成情况。
- 跟进原因分布。
- 本周结论和下周建议。

### 4.9 AI 失败兜底

- AI 调用失败时，返回明确错误。
- 任务仍允许完成。
- 用户可手动填写总结。
- 失败信息记录到任务历史，不阻塞主流程。

## Phase 4：权限、日志与稳定性

目标：把治理功能纳入现有账号权限体系和审计体系。

### 4.10 权限建议

| 权限 | 说明 |
|---|---|
| `follow.view` | 查看异常门店治理 |
| `follow.task.create` | 创建治理任务 |
| `follow.task.edit` | 编辑任务门店和筛选条件 |
| `follow.task.status` | 完成、归档、恢复任务 |
| `follow.record.edit` | 编辑门店跟进记录 |
| `follow.summary.generate` | 生成 AI 总结 |
| `follow.summary.confirm` | 确认保存总结 |
| `follow.data.refresh` | 刷新或同步跟进数据 |

如短期不新增细粒度权限，可先复用 `follow.view`、`follow.distribution.view`、`follow.data.refresh`，但状态变更和总结确认建议尽快拆分。

### 4.11 操作日志

以下操作需要记录：

- 创建任务。
- 修改任务门店。
- 保存跟进记录。
- 完成任务。
- 归档任务。
- 恢复任务。
- 生成 AI 总结。
- 人工确认总结。
- 修改门店治理状态或评级。

日志内容包括操作人、操作时间、模块、动作、对象 ID、变更前后内容。

## 7. 推荐开发顺序

1. 补齐治理库 schema 和迁移兼容逻辑。
2. 实现筛选预览 API，优先完成到店数环比上周/上月阈值筛选。
3. 实现任务创建和保存门店快照 API。
4. 实现任务状态流转 API，并写入任务历史。
5. 在前端增加新建任务和筛选门店交互。
6. 增加门店跟进编辑能力。
7. 增加 AI 总结草稿、编辑确认和保存。
8. 补齐权限、日志、异常提示。
9. 执行本地接口测试、类型检查、构建和浏览器验证。
10. 更新使用说明和验收清单。

## 8. 风险与处理

| 风险 | 处理 |
|---|---|
| 旧数据表字段不一致 | 使用 schema 检查和兼容性补字段，避免破坏已有数据 |
| 日报日期格式不统一 | 统一通过日期归一化函数处理 |
| 环比同期无数据 | 前端展示无对比数据，不纳入下降筛选或按空值处理 |
| 连续上榜口径变化 | 保存任务快照，历史任务不随规则变化重算 |
| AI 服务不可用 | 支持手动总结，不阻塞任务完结 |
| 权限过粗 | 短期复用现有权限，后续拆分细粒度权限 |
| 旧端口服务缓存 | 本地开发明确后端端口和前端代理，避免打到旧服务 |

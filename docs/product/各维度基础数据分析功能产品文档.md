# 各维度基础数据分析功能 — 产品文档（V1.0）

## 一、功能概述

### 1.1 要解决什么问题

当前系统已经有门店级运营日报和各类基础指标，但缺少**从时间、渠道、车系等维度交叉分析**的能力。管理者需要能够回答类似这样的问题：

- "5月份 APP投流渠道的 AION UT 线索有效率是多少？对比4月是涨了还是跌了？"
- "哪些渠道×车系的组合线索有效率持续偏低，下个月应该减少投放？"
- "AION i60 在垂媒线索渠道的到店率趋势如何？"

### 1.2 整体思路

**三层架构**，从数据到洞察逐层递进：

```
┌─────────────────────────────────────────────────┐
│ 第三层：分析洞察（图表 + AI 小结）                      │
│ 入口：首页 →「数据分析」                               │
│ 折线图 / 柱状图 / 筛选器 / AI自动解读                   │
└──────────────────┬──────────────────────────────┘
                   │ 点击跳转（带筛选条件）
┌──────────────────▼──────────────────────────────┐
│ 第二层：数据浏览表                                   │
│ 入口：经销商管理 →「各维度基础数据」卡片                    │
│ 按年月/日期 × 二级渠道 × 邀约意向，展示宽表明细             │
└──────────────────┬──────────────────────────────┘
                   │ 预计算
┌──────────────────▼──────────────────────────────┐
│ 第一层：宽表 dimension_base_data（DuckDB中间库）         │
│ 按 年月/日期 + 二级渠道 + 邀约意向 三维交叉聚合             │
│ 包含20项业务指标，兼容运营日报口径                        │
└─────────────────────────────────────────────────┘
```

| 入口 | 位置 | 路由 | 页面内容 |

入口一宽表内支持一键跳转入口二，跳转时自动带上当前筛选的年月/渠道/车系条件。

## 三、数据层：宽表 `dimension_base_data`

### 3.1 数据来源

| 源字段 | 来源表 | 映射说明 |
|:---|:---|:---|
| `assign_date` | `mart_leads` | 线索下发日期，据此衍生 `year_month`（如 2026-05） |
| `invite_intent` | `mart_leads` | 邀约意向，作为"车系"维度。需新增同步至 DuckDB |
| `channel_2` | `mart_leads` | 二级渠道，作为"渠道"维度 |
| 20项业务指标 | `mart_leads` + `fact_daily_visit` | 计算口径与运营日报 `report_dealer_daily` 完全一致 |

### 3.2 宽表字段设计

**维度字段（聚合键）：**

| 字段名 | 类型 | 说明 | 示例 |
|:---|:---|:---|:---|
| `year_month` | VARCHAR(7) | 年月 | `2026-05` |
| `report_date` | DATE | 具体日期 | `2026-05-14` |
| `channel_2` | VARCHAR | 二级渠道 | `新媒体-经销店`、`垂媒线索`、`广宣投放线索` |
| `invite_intent` | VARCHAR | 邀约意向（车系） | `AION UT`、`AION i60`、`AION RT` |

> **说明**：一条记录的粒度 = 某个年月下的某个日期 + 某个二级渠道 + 某个车系。比如 `2026-05 / 2026-05-14 / 垂媒线索 / AION i60`。

**业务指标字段（与运营日报完全一致，共 20 项）：**

| 字段名 | 类型 | 说明 |
|:---|:---|:---|
| `lead_count` | INTEGER | 线索量 |
| `valid_lead_count` | INTEGER | 有效线索量 |
| `valid_lead_rate` | DOUBLE | 线索有效率（%） |
| `valid_local_lead_count` | INTEGER | 有效本地线索量 |
| `local_lead_count` | INTEGER | 本地线索量 |
| `n60_lead_count` | INTEGER | N60 线索数（邀约意向 = AION N60） |
| `n60_follow_30min_count` | INTEGER | N60 及时跟进数 |
| `follow_30min_count` | INTEGER | 30分钟跟进数 |
| `follow_30min_task_count` | INTEGER | 30分钟跟进任务数 |
| `follow_30min_rate` | DOUBLE | 30分钟跟进率（%） |
| `day3_3follow_task_count` | INTEGER | 三天三次跟进任务数 |
| `day3_3follow_count` | INTEGER | 三天三次跟进完成数 |
| `day3_3follow_rate` | DOUBLE | 三天三次跟进率（%） |
| `to_shop_count` | INTEGER | 到店数 |
| `lead_to_shop_rate` | DOUBLE | 线索到店率（%） |
| `local_lead_to_shop_rate` | DOUBLE | 本地线索到店率（%） |
| `valid_lead_to_shop_rate` | DOUBLE | 有效线索到店率（%） |
| `valid_local_lead_to_shop_rate` | DOUBLE | 有效本地线索到店率（%） |
| `new_media_self_lead_count` | INTEGER | 新媒体自店线索量 |
| `new_media_self_valid_lead_count` | INTEGER | 新媒体自店有效线索量 |

### 3.3 口径说明

所有指标的计算口径与 `report_dealer_daily` 表**完全一致**，唯一的区别在于：
- `report_dealer_daily` 按**门店**聚合
- `dimension_base_data` 按**二级渠道 × 邀约意向**聚合

具体每个指标的计算公式参考已有产品文档《线索运营日报指标体系产品文档_一级渠道空值过滤版.md》。

### 3.4 预计算方式

纳入 DuckDB 管理器的 `compute_*` 调度链，与 `report_dealer_daily` 同步更新：

- 按日更新：当天日期的宽表行
- 按月更新：当月所有日期的宽表行（重新计算当月的年月级汇总）

### 3.5 前端数据源补充

需要在 `mart_leads` 中新增 `invite_intent` 字段的同步（目前该字段存在于 SQLite `线索表` 中但未同步到 DuckDB）。

### 4.5 导出功能规格

**触发方式：** 点击筛选工具栏的「⬇ 导出Excel」按钮。

**导出范围：** 当前筛选条件对应的**全量数据**（不是仅当前页），即用户从 N 万条总数据中通过筛选器筛选出 500 条，导出的就是这 500 条。

**导出流程：**
1. 用户点击「⬇ 导出Excel」按钮
2. 前端调用后端 API（不带 page/page_size 分页参数），获取符合当前筛选条件的全量数据
3. 前端将数据转为 Excel 并触发浏览器下载

**导出文件格式：**
- 文件名：`各维度基础数据_2026-05.xlsx`（年月为筛选的年月，如未选则用 `全部月份`）
- Sheet 名称：「各维度基础数据」

### 4.6 表格规格

- 表头冻结（纵向滚动时固定）
- 前两列（年月、日期）冻结（横向滚动时固定）
- 支持分页（每页 50 条，也可选 100/200）
- 数据按 `year_month DESC, report_date DESC, channel_2, invite_intent` 排序
- 点击【跳转分析页】按钮，跳转 `/data-analysis` 并带上当前筛选条件作为 URL 参数（如 `?year_month=2026-05&channel_2=垂媒线索&invite_intent=AION+UT`）

### 5.6 AI 小结

基于当前筛选维度下的数据，自动生成文字摘要。

**生成内容：**
1. **关键指标概览**：如"5月垂媒线索渠道的 AION i60 线索量为 1,280，有效率 62.3%"
2. **对比发现**：如"对比4月，线索有效率下降 5.2 个百分点，主要受垂媒渠道影响"
3. **异常提醒**：如"AION UT 在新媒体-区域渠道的到店率仅 2.1%，显著低于其他车系（平均 8.5%）"
4. **建议行动**：如"建议减少新媒体-区域渠道对 UT 的预算倾斜"

**触发方式：**
- 每次筛选条件变化后自动刷新
- 也可点击【重新分析】按钮手动触发

**技术实现：**
- 后端生成分析数据（环比、同比、排名、异常检测）
- 前端调用 LLM API 生成自然语言小结（使用系统已有的 AI 能力或接入外部 LLM）
- 分析数据 + 筛选描述 → Prompt → AI 小结文字

## 六、核心数据逻辑

### 6.1 dimension_base_data 预计算 SQL（核心逻辑）

```sql
INSERT INTO dimension_base_data
SELECT
    strftime(assign_date, '%Y-%m') AS year_month,
    assign_date AS report_date,
    channel_2,
    invite_intent,
    -- 线索量
    COUNT(*) AS lead_count,
    -- 有效线索量
    SUM(CASE WHEN lead_status NOT IN ('异地','无效','未跟进')
              AND channel_3 != 'APP-试驾'
         THEN 1 ELSE 0 END) AS valid_lead_count,
    -- 有效线索量 / 线索量 * 100
    ...
FROM mart_leads
WHERE follow_cutoff_time IS NOT NULL
  AND channel_1 = '线上'
  AND channel_2 IS NOT NULL AND channel_2 != ''
  AND invite_intent IS NOT NULL AND invite_intent != ''
GROUP BY year_month, report_date, channel_2, invite_intent
```

所有20项指标的计算 CASE WHEN 条件与 `report_dealer_daily` 的 `m_` 前缀字段完全一致，差异仅在于 GROUP BY 维度从 `dealer_id` 变为 `(year_month, report_date, channel_2, invite_intent)`。

到店数 `to_shop_count` 需要 JOIN `fact_daily_visit`，与现有逻辑相同。

### 6.2 数据分析页后端 API

| 接口 | 方法 | 路径 | 说明 |
|:---|:---|:---|:---|
| 分析数据查询 | GET | `/api/data-analysis/data` | 返回指定维度下的指标数据，用于图表渲染 |
| AI 小结 | GET | `/api/data-analysis/summary` | 返回基于当前筛选的 AI 分析文本 |

**分析数据接口参数**：`year_month`（必填）、`start_date`（选填）、`end_date`（选填）、`channel_2`（选填多值）、`invite_intent`（选填多值）、`metric`（选填，默认有效率）。

## 2. 背景与问题

当前「线索运营监控系统」已经具备首页看板、跟进记录、跟进次数分布、运营数据入口、客流明细、客流统计、数据查询、经销商管理、运营日报、重点店风向监测等已落地业务能力。随着系统从单人或少数人使用逐步转向小团队内部协作，需要补齐账号权限体系。

本次权限体系建设不是做一套脱离业务场景的通用权限平台，而是在现有「线索运营监控系统」中补齐以下能力：

1. 用户需要先登录后使用系统。
2. 不同角色能够访问的页面、按钮、接口不同。
3. 关键操作需要能追溯到人、时间、IP、模块和操作内容。
4. 当前小团队内部使用，不接入企业 SSO。
5. V1 只服务总部内部人员，门店侧、区域侧、大区/战区数据隔离仅做模型预留。

## 3. 已确认产品口径

## 4. 权限数据存储建议

### 4.1 建议方案

账号、角色、权限、登录日志、操作日志等权限体系数据，建议写入本地 SQLite 主库：

```text
/Users/bournelll/Desktop/线索运营/leads.db
```

DuckDB 中间库继续用于页面查询、指标预计算、聚合分析，不承载账号密码、权限规则等认证授权数据。

### 4.2 建议理由

1. **SQLite 是当前业务主库，适合保存事务型数据**  
   账号、角色、权限、日志属于系统管理类事务数据，需要频繁增删改查，并且需要长期保存。SQLite 更适合这类数据。

2. **DuckDB 更适合分析查询，不适合做认证授权主存储**  
   当前 DuckDB 在系统中的定位是中间层和预计算层，用于提升页面查询和指标聚合性能。账号密码、角色授权、操作日志不属于预计算指标，不建议混入 DuckDB。

3. **安全边界更清晰**  
   密码哈希、用户状态、角色权限等敏感数据应保存在主库中，由后端认证授权逻辑直接读取。DuckDB 只消费业务分析数据，避免敏感认证数据进入分析层。

4. **降低开发复杂度**  
   V1 是小团队内部使用，本地 SQLite 已经存在，直接新增系统表即可，不需要引入新的数据库或服务。

5. **便于后续扩展**  
   如果未来系统要迁移到 MySQL、PostgreSQL 或服务端数据库，`sys_users`、`sys_roles`、`sys_permissions` 等系统表可以整体迁移，模型不会被 DuckDB 的分析定位绑定。

### 4.3 最终建议

V1 采用：

```text
权限管理数据：SQLite leads.db
业务分析加速：DuckDB 中间库
```

该方案最符合当前系统形态，也便于快速落地。

## 5. 产品目标

### 5.1 V1 目标

1. 支持本地账号密码登录。
2. 支持登录态保持和退出登录。
3. 支持总部管理员维护账号。
4. 支持总部管理员维护角色。
5. 支持菜单、页面、按钮权限控制。
6. 支持后端接口权限校验。
7. 支持登录日志记录。
8. 支持关键操作日志记录。
9. V1 数据权限全部为全系统数据可见。
10. 权限模型预留大区、战区、门店、自定义门店范围扩展能力。

### 5.2 V1 不做内容

1. 不接入企业 SSO。
2. 不做 MFA 多因素认证。
3. 不做字段级权限。
4. 不做审批流式授权变更。
5. 不做复杂 ABAC 条件权限。
6. 不做门店侧登录入口。
7. 不做门店侧独立工作台。
8. 不做首次登录强制修改密码。
9. 不做连续输错密码锁定账号。
10. 不正式开放大区、战区、门店角色登录。

## 8. 功能需求

## 8.1 登录认证

### 8.1.1 登录页

用户通过本地账号密码登录系统。

#### 页面字段

| 字段 | 说明 |
|---|---|
| 登录账号 | 必填，用户登录账号 |
| 密码 | 必填，密文输入 |
| 登录按钮 | 提交登录 |
| 错误提示 | 展示登录失败原因 |

#### 业务规则

1. 未登录用户访问系统业务页面时，跳转登录页。
2. 登录成功后进入系统首页。
3. 登录失败时展示错误提示。
4. 登录成功和登录失败均记录登录日志。
5. 停用账号禁止登录。
6. V1 不做首次登录强制改密。
7. V1 不做连续输错锁定。

### 8.1.2 退出登录

用户可主动退出系统。

#### 业务规则

1. 用户点击退出登录后，清除当前登录态。
2. 退出后再次访问业务页面，需要重新登录。
3. 退出登录记录操作日志或登录日志。

### 8.2.1 账号列表

### 8.2.2 账号操作

| 操作 | 权限要求 | 说明 |
|---|---|---|
| 新建账号 | 总部管理员 | 创建总部内部账号 |
| 编辑账号 | 总部管理员 | 修改基本信息、角色、组织 |
| 启用账号 | 总部管理员 | 启用已停用账号 |
| 停用账号 | 总部管理员 | 停用后禁止登录 |
| 重置密码 | 总部管理员 | V1 可重置为系统默认初始密码或生成临时密码 |
| 查看最近登录信息 | 总部管理员 | 查看最近登录时间和 IP |

### 8.2.3 业务规则

1. 登录账号必须唯一。
2. 一个账号可以绑定多个角色。
3. 用户不能停用自己当前正在使用的账号。
4. 内置管理员账号不可被停用。
5. 停用账号后禁止再次登录。
6. 账号新增、编辑、启用、停用、重置密码均记录操作日志。
7. 日志中不得记录明文密码。

## 8.3 角色管理

总部管理员可维护角色和权限配置。

### 8.3.1 角色列表

#### 列表字段

| 字段 | 说明 |
|---|---|
| 角色编码 | 系统唯一编码 |
| 角色名称 | 例如总部管理员、总部运营人员 |
| 角色说明 | 角色用途说明 |
| 是否内置 | 内置角色不可删除 |
| 数据范围 | V1 均为全系统数据 |
| 绑定账号数 | 当前角色绑定账号数量 |
| 创建时间 | 角色创建时间 |

### 8.3.2 角色操作

| 操作 | 权限要求 | 说明 |
|---|---|---|
| 新建角色 | 总部管理员 | 创建自定义角色 |
| 编辑角色 | 总部管理员 | 修改角色名称、说明、权限 |
| 删除角色 | 总部管理员 | 仅允许删除未被引用且非内置角色 |
| 配置菜单权限 | 总部管理员 | 控制导航可见性 |
| 配置页面权限 | 总部管理员 | 控制页面访问 |
| 配置按钮权限 | 总部管理员 | 控制页面操作按钮 |
| 配置数据范围 | 总部管理员 | V1 默认全系统，配置位预留 |

### 8.3.3 业务规则

1. 内置角色不可删除。
2. 已被账号引用的角色不可直接删除。
3. 多角色用户的功能权限取并集。
4. V1 多角色用户的数据权限也取并集，但由于 V1 仅总部角色，结果均为全系统数据。
5. 角色权限变更后，用户刷新权限或重新登录后生效。
6. 角色新增、编辑、删除、权限变更均记录操作日志。

## 8.4 菜单、页面、按钮权限

### 8.4.1 权限层级

V1 权限资源分为四类：

```text
模块权限：控制一级导航或功能模块是否可见
页面权限：控制用户是否可进入页面
按钮权限：控制刷新、同步、筛选、查询、排序、下钻、导出、新增、编辑、删除等已实现或本次新增操作按钮
接口权限：后端真实鉴权点
```

前端负责展示控制，后端负责最终授权校验。

## 12. 权限控制规则

## 12.1 前端规则

1. 未登录用户不能访问业务路由。
2. 前端根据 `/api/auth/me` 返回的权限控制导航展示。
3. 前端根据按钮权限控制按钮展示。
4. 无页面权限时展示无权限页面。
5. 前端控制只用于用户体验，不作为最终安全边界。

## 12.2 后端规则

1. 当前已实现业务接口和本次新增账号权限接口默认需要登录，登录接口和健康检查接口除外。
2. 当前已实现接口需按 8.4.2 权限点接入接口权限校验，重点包括：
   - 首页与数据刷新：`/api/dashboard`、`/api/refresh/trigger`
   - 跟进记录与跟进次数分布：`/api/follow-up/distribution`
   - 客流明细与客流统计：`/api/customer_visit/stats`、`/api/customer_visit/detail`、`/api/customer_visit/export`、`/api/visit_stats`、`/api/visit_stats/export`
   - 数据查询：`/api/query/tables`、`/api/query/table/<table_name>/schema`、`/api/query/detail`、`/api/query/aggregate`、`/api/query/export`、`/api/query/filterable/<table_name>`、`/api/query/groupable/<table_name>`、`/api/query/aggregatable/<table_name>`
   - 经销商运营日报：`/api/dealer-daily-report`、`/api/dealer-daily-report/export`、`/api/dealer-daily-report/export-template`、`/api/dealer-daily-report/export-custom-range`
   - 账号权限新增接口：`/api/auth/me`、`/api/auth/logout`、`/api/admin/users`、`/api/admin/roles`、`/api/admin/permissions`、`/api/admin/audit-logs`、`/api/admin/login-logs`
3. 后端根据当前用户角色和权限资源校验接口访问权限。
4. 无权限返回 403。
5. 未登录或登录过期返回 401。
6. 关键操作写入操作日志。
7. V1 数据范围统一返回全系统数据。
8. 后续启用大区、战区、门店权限时，在统一数据范围函数中扩展过滤逻辑。

## 13. 安全要求

1. 密码必须哈希存储，不允许明文存储。
2. 登录接口不返回密码哈希。
3. 登录失败提示不泄露敏感系统信息。
4. Token 或 Session 需要有过期机制。
5. 退出登录后当前登录态失效。
6. 停用账号后禁止重新登录。
7. 日志不得记录明文密码、Token、密钥等敏感信息。
8. 重置密码时不得在日志中记录明文密码。

## 15. 验收标准

## 15.1 登录认证

1. 未登录访问业务页面会跳转登录页。
2. 正确账号密码可登录。
3. 错误账号密码不可登录。
4. 停用账号不可登录。
5. 登录成功后可获取当前用户、角色、权限。
6. 退出登录后不能继续访问业务页面。
7. 登录成功和失败均有登录日志。

## 15.2 账号管理

1. 总部管理员可新建账号。
2. 总部管理员可编辑账号信息。
3. 总部管理员可绑定和调整账号角色。
4. 总部管理员可启用或停用账号。
5. 用户不能停用自己。
6. 登录账号不能重复。
7. 账号变更会记录操作日志。

## 15.3 角色管理

1. 总部管理员可新建角色。
2. 总部管理员可编辑角色。
3. 总部管理员可配置菜单、页面、按钮权限。
4. 内置角色不能删除。
5. 被账号引用的角色不能直接删除。
6. 角色权限变更后刷新权限或重新登录后生效。
7. 角色变更会记录操作日志。

## 15.4 权限控制

1. 没有页面权限的用户看不到对应导航、入口卡片或页面入口。
2. 没有页面权限的用户直接访问 URL 时被拦截。
3. 没有按钮权限的用户看不到对应刷新、同步、筛选、查询、排序、下钻、导出等操作按钮或操作入口。
4. 直接调用无权限接口时，后端返回 403。
5. 前后端权限结果一致。
6. 当前首页中仅展示但未实现独立页面的卡片，不作为 V1 独立权限验收对象。
7. 账号权限模块可管理当前系统已实现页面和操作对应的权限点。

## 15.5 日志审计

1. 登录成功和失败均记录登录日志。
2. 账号、角色、权限、首页同步、数据查询、业务查询、下钻、导出等关键操作记录操作日志。
3. 日志包含操作人、时间、IP、模块、动作、对象和结果。
4. 日志不包含明文密码、Token、密钥等敏感内容。
